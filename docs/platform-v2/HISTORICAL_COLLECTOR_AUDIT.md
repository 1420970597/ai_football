## 实现与定义

### R01 请求冷却与失败分类

1. HTTP 429 和业务限流码继续使用同一限流异常，额外保留固定操作名、HTTP 状态和解析后的 Retry-After 秒数。操作只允许赛程快照、批量盘口、单场盘口三种；不保存 URL、响应原文或凭据。
2. Retry-After 支持非负秒数与有时区 HTTP 日期，拒绝非有限数、负数、超过 128 字符的值及无法解析的文本；向上取整且上限 900 秒。缺失时使用基础 60 秒。连续限流依次等待 60、120、240、480、900 秒，之后不再增加；尊重更长的有效 Retry-After 但仍受 900 秒预算限制。
3. 限流发生后不再启动尚未发送的盘口批次；已获得赛程及成功盘口继续上传。限流等待没有 WebSocket 唤醒通道；正常恢复轮询后清零限流连续次数，并恢复通常调度。
4. 每轮输出脱敏类别、固定操作名、HTTP 状态、耗时、下次等待、配置版本和最后入库成功时间。网络、域名解析、会话、权限、协议、配置、限流与入库失败分别归类。域名失效仅在异常链有 DNS 证据时判定，不根据异常文本猜测。
5. 部分盘口失败的首个分类和操作不再丢失。HTTP 入库 503 会显示为 ingestion/503，不能误报为上游权限问题。未知异常只显示类型。限流即便其余快照完整也保持 partial 状态。

轮询计数中，poll_successes 表示一次采集返回且上传完成，允许部分快照；poll_failures 表示本轮抛错，二者合计等于已结束轮数。last_success_at 同样表示上传成功，last_complete_at 只在快照无本轮问题时更新。它们都不能证明所有旧报价新鲜，须同时看已有 freshness 和源报价时间。

### P18-08 订阅覆盖与恢复证据

1. 订阅仍按 200 场分帧、全量覆盖，不以 20 场为边界。只有 socket.send 成功的当前帧才纳入 subscription_requests_sent；发送中断会留下准确的本地未发送场数和比例。连接断开后清除本连接发送覆盖，不能沿用上一连接的成功数。
2. subscription_send_missing_ratio 是本地发送缺口；subscription_miss_ratio 与 subscription_confirmed_fixtures 始终为未知，subscription_confirmation_state=unverified。尚无经过核验的逐场上游确认协议，不能以本地发送成功或消息沉默伪造真实漏订阅率。
3. 新增入队丢弃比例与补同步信号/失败计数。resync_signals 证明回调通知了轮询补采，不表示完整补采已经完成；是否恢复需结合后续完整轮询、报价源时间和队列。
4. WebSocket 的业务限流码、权限拒绝与 HTTP 握手 429 进入脱敏分类和等待，不能继续当作畸形推送吞掉。HTTP 403 本身不证明会话过期，不触发登录。

### P41 阈值状态

所有阈值使用有界标量状态、连续样本和恢复迟滞，不创建外部通知，也不重复累加同一故障的状态转变。无效/缺失样本不能宣告健康或消除已有告警。

| 诊断 | 触发 | 恢复 | 证据含义 |
| --- | --- | --- | --- |
| 轮询 | 连续两轮失败或部分/陈旧状态 | 连续三轮无本轮问题 | 轮询链路恢复，不证明历史报价全新 |
| 本地订阅 | 连续两次发送周期缺口至少 5% | 连续两次周期缺口为零 | 仅本地发送恢复 |
| 队列 | 连续两次样本占用至少 80% | 连续三次样本占用不超过 25% | 有界接收队列积压恢复 |
| 推送投递 | 连续两次回调失败 | 连续三次回调成功 | 回调投递恢复，不是页面确认 |

状态为 unknown、pending、active、recovering、clear，另记录 transitions、recoveries、changed_at、recovered_at。丢弃时保留已有自动补同步，投递失败重试原批次，不丢独立盘口更新。
