# Android、入口与发布历史缺口修复记录

更新时间：2026-10-27。状态：实施中；本记录仅覆盖本次委派范围，不替代全局任务验收。

## 本轮目标与边界

- 在项目内实现外置 Android 签名材料的容器注入、签名身份核验和候选包证据，不生成或冒充正式密钥。
- 增加按提交绑定的正式发布门禁；缺真实设备、生产入口、恢复和业务链路证据时明确拒绝正式发布。
- 复核当前 Nginx 入口已有请求体、限流、超时及内部路由隔离，补有实际 HTTP 请求的 Docker 验证。
- 不修改全局任务/进度、其他业务模块或 Git；不访问项目外文件，不执行资金操作。

## 当前证据与缺口

- P36：客户端已有 HTTPS 配对、Keystore、同源导航与离线状态实现；历史 17 项单元/TLS 测试通过，设备 UI 曾受 System UI ANR 阻断，不能记为实际配对通过。
- P37：固定 Docker 工具链和开发候选输出存在；正式签名注入未实现，临时 Debug 签名不能保证跨构建升级。
- P44：当前入口已限制 1 MiB 请求、30 r/s（burst 60）和内部路由，需补隔离 HTTP 行为验证；生产 HTTPS 与证书不在本轮虚构。
- P45：现有发布工作流固定为开发预发布；需独立的签名候选路径和正式证据门禁，不能将旧预发布冒充稳定发行。

## 已实现的交付边界

- Android 版本和版本码可由构建属性显式注入；默认开发构建契约保持原值。
- 外置签名入口只挂项目内 0700 目录及四份 0600 文件，apksigner 使用密码文件；不把密码放入构建参数或输出，核对外部登记证书和网络权限。正式密钥仍由签名保管人提供，测试签名只验证管线。
- 不覆盖上次签名输出；每个候选含 APK SHA-256、签名证书、源码父提交与工作树状态。Debug、额外权限、错误包名/版本、可调试和 testOnly 均拒绝。
- 稳定门禁校验八类当前提交真实证据、七天时效、命令与退出码、项目内产物哈希、设备与升级的精确 APK 哈希。候选签名成功不会创建正式 Release。
- Nginx 增加请求头、请求体、发送和 keepalive 超时；既有体积与速率限制用真实 HTTP 请求验证。未更改当前业务容器或外部域名证书。
- 设备脚本支持显式主机/端口/设备/HTTPS 样本来源/输出目录；预检只允许项目网络并输出结构化阻塞原因，后续可在受控设备继续 UI 流程。

## 证据位置

本轮构建、预检和测试签名均只在项目被忽略的运行目录或 Android 构建目录。两轮测试 APK SHA-256 均为 `7304747c631019eca40b3e44b4aa7380f34a223b761e223aeecb134f71124e8f`，非正式身份、不可发布。最终源码父提交记录为 `8a13716962d2022ea16b6083f13c840c57ed42bc`，包含本轮未提交改动，清单明确标记脏树；不能声称为该提交的已发布源码。

最终 APK、签名核验、release Lint、测试 XML、源文件摘要和清单位于 `android/build/signed-artifacts/`；首轮候选位于 `.runtime/android-signed-fixture-first-artifacts/`；两轮完整构建日志分别为 `.runtime/android-signed-fixture-build.log`、`.runtime/android-signed-fixture-final-build.log`；设备预检与工具构建日志位于 `.runtime/android-device-evidence/`。所有临时签名秘密已在复验结束后删除，仅保留公开证书摘要。

本次工具记录另有可审计失败：首次新增 Python 测试使用错误引号，Docker 解析退出 1，修正后六项最终通过；一次执行器多段补丁格式错误与少量 JSON/JavaScript 传输引号错误均未执行文件或应用；一次 `rm -f` 形式的临时材料清理被自动审核拒绝，未删除任何文件，随后改用受限 Docker 对四个固定文件 `unlink` 并核验，退出 0。失败未用于降低生产、设备或签名门槛。
