## 源时间字段核对

- timestamp 将正数秒或毫秒转换为 UTC，拒绝零、未知、非有限数和无时区日期；不回退 now。离线断言同一秒值/毫秒值解析相同。
- parse_quotes 读取 option.ctsp，否则 block.ctsp。项目内 v1 的 collector/leyu_client.py 第 757—759、818—823 行明确把块级 ctsp 定义为赔率变更时间戳，与 hl 同级并应用于该块选项。当前已实现块级兜底，没有证据证明应改成比赛开赛时间、HTTP 响应时间或任意其它字段。
- 相同价格但新 ctsp 仍会形成更新；代码没有“价格相同便不更新时间”的过滤。离线探针已确认此点。若上游未变价且 ctsp 不变，保留原 ctsp 是事实，重复 HTTP 读取、WS 心跳或订阅成功不能让它变新。
- WS hls/hls2 适配使用块 ctsp/t 或已核验行 time/t/ctsp；事件外层还支持 ts，但不能据无相应盘口样本把任意外层事件时间扩散为每项报价源时间。未观察到当前故障由秒/毫秒或错误时区导致的证据。
- 采集健康函数使用 60 秒统计，交易/MCP 使用实际 15 秒门槛，两者不是同一可交易判定；不能因健康显示 partial/fresh 就认为所有推荐都可接受。

## 缺陷一：完整旧 HTTP 会回退较新的 WS 内存投影

原 runtime._collect 只对 markets_complete=false 合并历史报价；为 true 时直接跳过比较并重建整个内存投影。因此已有新 WS active/2.20/t2，可以被旧完整 HTTP suspended/2.00/t1 回退。API 的报价 upsert 有源时间单调约束，通常会拒绝直接回退数据库；但后续缺状态证据的 WS 会继承已回退的内存 suspended，生成较新时间的错误停盘状态，再被数据库接受。这不是只影响缓存显示的无害覆盖。

网络禁用 Docker 的修复前可重放探针输出：complete_http_rolls_projection_back=true、after_http_status=suspended、next_unknown_status_push_inherits_rolled_back_status=suspended。没有改 TTL 或构造真实上游请求。

### 已修复的策略

同一规范盘口键在完整或部分 HTTP 中均比较真实源时间；较旧、无效或未知 HTTP 不得覆盖已有已知报价，保留完整一致的旧对象而非把新时间与旧价格拼接。比较标准化为有时区 datetime，不做 ISO 文本字典序推断。

完整快照缺失项仍删除，保留原来完整下架/状态语义。仅当 HTTP 进行期间已有成功接受的新 WS 更新，而完整响应未包含该键时，以内存 push revision 识别竞争，保留该项并将该次 markets_complete 降为 false，避免 API 错误关闭。该标记不把未知时间 WS 当事实，也不建立虚构的跨盘口快照时间水位；下一次无竞争完整快照仍能删除。revision 只保存当前活跃键，比赛/盘口消失后回收。

未知源时间继续未知。接收时间仅用于接收证据，不参与源版本优先级。本轮没有改 fixture 比分/状态合并、刷新调度、MCP 或数据库逻辑。

## 缺陷二：15 秒消费时限与全量轮询刷新架构不匹配

当前默认完整轮询间隔为 20 秒、滚球补盘周期 20 秒、临近赛前 60 秒、远期赛前 300 秒；每轮最多 96 场，默认每批 12、单并发、批间隔 1 秒。预算按 live/live/near/far 轮转，保证最终覆盖但不保证 15 秒内所有报价可读。轮询等待在该轮采集和入库之后，不能把“20 秒配置”当 20 秒端到端覆盖上限。

### 可测修复方向，交主线实施

分开赛程低频全量与有界精确报价刷新；只对已由当前审核任务完整检索并唯一选中的赛事/盘口发真实的限额刷新需求，按比赛去重与合并并发、共享现有冷却/退避，设置整体截止，优先实时审核而不饥饿全量覆盖。MCP 工具必须重新读取系统最新投影并接受原始 ctsp 门槛；若上游仍返回旧 ctsp，结果仍 stale，不得用按需调用成功制造新鲜时间。盘口关闭/变线/歧义时拒绝推荐而非换盘。

先用纯替身验证同场重复刷新合并、两个任务共享结果但身份隔离、超时和限流不放大上游请求、旧消息不发实时刷新、完整分页不被截断、返回旧 ctsp 仍拒绝；之后由主线在授权环境测精确刷新源至读延迟。增加并发或提高预算不能作为未经测量的直接结论，本轮未对上游压测。

## 本轮结论与剩余边界

最直接确定的可修代码问题是旧完整快照回退新推送，已局部修复并冻结。刷新预算与消费时限的结构性不匹配需要按任务精确刷新和容量证据解决。当前没有证据支持改源时间字段、给不变价续写时间或提高 TTL；本轮不宣布全部新鲜度问题已经根治。主线调度/MCP、生产采集健康、真实专家信号和完整回归继续分别验收。
