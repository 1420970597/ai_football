# 首页专家关联仅展示可执行推荐（2026-11-12）

## 工作包

- 目标：按用户补充要求，在展示前排除会触发“推荐、来源或当前比赛盘口不满足实盘条件”的推荐；保留未结算条件。
- 责任目录：services/api/app/routes/、web/app/、tests/、docs/platform-v2/、reports/；生产镜像固定同步到主检出infra/production/。
- 前置依赖：网页分支24a4c22a、线上API61acb952；当前public模块必须匹配线上，不从较旧主检出重建。
- 当前证据：orders.eligible_signal还检查五分钟推荐/原文时效、原文未来时间、媒体ready、阶段一致、原生标识与执行支持范围；现有首页只检查pending和来源可见性。报价缺失、关闭、过期也不应展示为可执行推荐。
- 缺口：未结算并不代表仍可下单；失效推荐仍占比赛分页和摘要名额。
- 设计决策：在比赛EXISTS和推荐摘要LIMIT前共用同一可执行筛选；精确匹配比赛、玩法、期间、盘口线、方向，独赢兼容空线与零线；按现有运行配置判断报价新鲜度。排除完场/取消、阶段切换、旧原文、不可执行玩法及缺少原生标识的盘口。不放宽下单校验；账户/会员/限额仍按本人校验，展示不构成接单保证。全部赛事、详情、历史统计不变。
- 实现动作：局部收窄公开首页查询并更新游标语义；补充全部拒绝分支、报价匹配/时效、混合有效无效、分页和上限的隔离测试，并与实际eligible_signal交叉核验；复用已有浏览器专项。
- 验收场景：上述任一推荐级失效条件均不展示；同场仅合格推荐；无合格推荐则不展示比赛；足球/篮球有效原生盘口保留；分页/上限按有效项计；无交易测试与生产测试数据写入。
- 失败处理：失败先定位并保留退出码，修复后重跑原检查；候选未通过不部署。仅更换API镜像，保留原镜像回滚，不回滚业务数据。
