# 订单预检与提交许可证据

日期：2026-10-27。对应 P12-03。范围：业务 API 的账户授权、订单复核及独立订单证据模块；没有修改执行器网络实现、数据库结构或冻结的盘口分片测试。

## 根因与最小实现

既有链路保存了推荐报价证据、订单预留快照、准备摘要、官方订单回执与结算，但预检通过和提交许可没有各自独立的追加记录。本次复用现有报价证据表的 order_attempt 类别和 order reference，不新增表、索引或结构迁移。

执行器仍在自身职责内完成原生盘口、金额限额和余额预检。API 收到准备摘要后，沿用原本人账户锁、订单锁、租约、版本、权益、当前报价和准备载荷校验。在同一个授权事务内依次：

1. 追加 preflight_validated，记录 API 已验证的规范化预检内容。
2. 将订单从 pending 转入 submitting，保存原准备摘要和发送租约。
3. 追加 submission_authorized，并指向同次预检证据。
4. 写入既有授权审计，事务提交后才返回发送许可。

任一阶段失败，前序证据及订单状态一起回滚。两个阶段都明确 submission_confirmed=false。它们不能证明已经发送、接单、成交、赛果或收益；实际结果仍以官方回执及原结算链为准。

## 内容与秘密边界

证据固定列记录系统比赛、玩法、期间、线、选项、价格及真实系统报价源时间。JSON 使用固定白名单，仅包含订单、尝试、本人账号内部编号、推荐、报价、绑定/配置/本人策略版本、准备摘要、金额、币种、拒绝变价策略、单关类型、原生比赛与盘口编号、比分基准及规范内容摘要。

证据构造函数不接收原 payload_json，不复制任意原始字段。原始请求头、会话、令牌、登录信息、密码、设备标识、完整配置及原载荷均不入证据。准备摘要只保留已有不可逆摘要值。source_updated_at 来自已复核系统报价，不能解释为上游原生预检接口额外提供了源时间。采集接收时间没有代替源时间。

独赢明确空线、亚洲玩法显式零线继续遵循 018 契约。证据中的规范数字使用十进制，不因缺线填零。保留实际提交对应的旧比分基准，同时记录许可时重新观测比分，避免将二者混淆。

## 幂等与不重发

记录主键由订单、尝试、阶段确定性生成。追加只执行 INSERT ON CONFLICT DO NOTHING，不执行 UPDATE 或 DELETE；发生冲突后重新读取全部固定列与完整证据，完全一致才视为存储幂等，任一差异返回 409 并保留首份内容。函数拒绝在事务外写入；正常入口始终先持订单锁。

这里的幂等只覆盖证据追加，不扩大资金许可重放。授权后的相同 HTTP 重放继续返回 409，不再次发放 permit。已发送未知结果保留两条阶段证据及原敞口，继续查单，不重新执行资金请求。本次未改变数据库已有业务角色的通用表权限，不能把应用层只追加实现宣称为独立数据库审计防篡改系统。

## 隔离验证

命令：sh .runtime/order-stage-evidence-20261027/run_isolated.sh。

沿用固定验证镜像；只读挂载本项目，容器内复制冻结副本；独立内部网络和临时 PostgreSQL。测试器 CPU 0.5、内存 512 MiB，临时数据库 CPU 0.35、内存 384 MiB。使用已存在的账户测试专用建库角色，只向临时库写入。原生所有网络请求均为 MockTransport，没有真实登录、上游比赛请求或投注。

第一轮六条新专项加关联回归共 66 项，52.317 秒，退出 0，日志 .runtime/order-stage-evidence-20261027/directed-first.log。补充两个边界专项及比分基准字段后重新冻结执行，共 68 项，53.822 秒，退出 0，日志 .runtime/order-stage-evidence-20261027/directed.log。git diff --check 本包路径退出 0。

新增八条行为场景：

1. 许可事务产生两个明确阶段；恶意额外秘密字段及真实模拟设备标识不落库；重放不重复许可。
2. 同规范摘要重复追加返回同一证据编号；不同摘要拒绝并保留首份内容。
3. 先存冲突阶段后调用授权，返回 409，订单仍 pending 且无准备摘要、无提交时间。
4. 第二阶段注入数据库故障，首阶段和 submitting 变化全部回滚，预留敞口保持。
5. 错准备摘要及过期报价拒绝，不生成任何阶段证据。
6. 模拟发送超时只发一次，留下两个未确认阶段、unknown 订单及原敞口，后续领取不重发。
7. 错尝试及事务外追加拒绝，没有证据写入。
8. 独赢空线完整经过授权，两阶段固定列和 JSON 保持空线且类别明确。

关联回归覆盖既有账户隔离、本人许可、敞口、取消、查单、官方回执、原生预检及盘口线契约。业务源码已冻结交主线完整套件与镜像重建；没有操作生产订单、全局待办、Git 提交或远端发布。
