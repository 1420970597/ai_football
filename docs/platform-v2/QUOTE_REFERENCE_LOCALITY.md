# 报价变化行复用引用索引

更新时间2026-11-06 06:11 UTC。E410研究中，生产仍E395，E408干净全套独立运行。

目标降低已匹配变化行再次读取冷UUID主键页的成本；责任为API报价写入、临时PG行为及只读计划证据。依赖E395单次物化引用映射及父赛事状态锁。E405已真实复现两次同PID连续DataFileRead后五秒超时，但未证明主键是唯一瓶颈。

设计先只在独立草案中将变化行UPDATE的匹配键由UUID改为同一不可变业务引用：fixture、market、period、null/zero盘口、selection，保留完整实时单调和差异重验。matched仍只查一次所有输入，INSERT仅处理未匹配项且保留冲突重验；变化行复用刚读取过的引用索引页。不同于E407，不携带或使用ctid，不预先锁不变报价。

验收先交替EXPLAIN ANALYZE和回滚比较79/2000输入的相同、旧、少量变化、全变化、半新增；只在临时数据库执行写计划。生产仅无ANALYZE的EXPLAIN验证是否实际选引用索引，未确认不宣称收益。更改业务前须通过并发UPDATE等待后新输入仍生效、较新并发值保留、插入冲突、稳定ID/xmin、完整快照和失败原子回滚。失败保留原SQL，不增加超时、不删除索引或数据，不混入正在冻结的E408候选。

下一步生成明确草案、隔离交替测量，然后决定是否进入业务实现；冷存储真实收益只能在上线后整窗中确认。
