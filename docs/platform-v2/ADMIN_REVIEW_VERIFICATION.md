# 管理员审核任务与受限重试

更新时间：2026-10-26。阶段：后端隔离验证通过；网页接入由客户端工作包验收，真实模型复核尚未执行。

## 接口契约

路由导出 `app.routes.admin_reviews.router`，前缀 `/api/v1/admin/reviews`。统一使用现有独立管理员会话；游客和普通用户不可访问。写请求继承管理员近期重新认证及 Cookie CSRF 要求。响应设置 `private, no-store`。

| 方法与路径 | 功能与约束 |
| --- | --- |
| `GET /`（实际路径无尾斜线） | 按 `expert_id`、`source_id`、`state`、`from_utc`、`to_utc` 筛选任务；`limit` 1—100，默认30，`cursor` 键集分页。 |
| `GET /{id}` | 任务状态、尝试与租约、消息原文、回复原文、作者稳定编号与TG昵称、图片访问地址、关联推荐及重试关系。 |
| `GET /{id}/traces` | 按轨迹序号正序连续分页，返回模型输出、工具参数/结果及时间；默认30条，最多100条。下一页非空则尚未读完。 |
| `POST /{id}/retry` | 请求体为 `{reason,idempotency_key}`，幂等键为UUID。成功201，返回 `{id,original_review_id,state,replayed}`。冲突409，携带可读说明及稳定原因代码。 |
| `GET /{id}/media/{index}` | 仅管理员读取远端原图；校验类型与已记录SHA-256，不返回内部对象键。上游失败503，不暴露异常路径或凭据。 |

列表按审核任务创建时间筛选，按 `(created_at,id)` 倒序。默认窗口是UTC当天零点前30天至次日零点，最大366天，明确返回 `from_utc`、`to_utc`、`time_basis=review_created_at_utc`。客户端分页时应继续携带返回的时间边界，避免跨UTC日期产生不同默认范围。时间必须带时区，结束时间为不包含的上界。

HMAC游标复用项目分页模块，绑定管理员编号、完整过滤范围及页大小；轨迹游标另绑定任务编号。更换过滤、管理员、任务或页大小，篡改签名均返回400。页面不是跨事务固定快照；任务状态实时变化时应刷新当前筛选。

详情中的重试关联展示最近30条，推荐摘要最多100条；完整任务可按作者和时间分页查询，完整审核轨迹使用独立轨迹接口。现有审核工具每次接受的推荐数量另有业务上限。本接口不导出通用数据库查询或账户信息。

轨迹保持模型与工具证据正文，隐藏结构化凭据字段、内部对象存储键及内嵌图片编码；原始文字仅在管理员授权范围内展示，图片通过授权媒体接口获取。读取不会触发模型调用。

## 重试事务与历史保护

只允许失败或未解决任务人工重试。旧任务状态、旧轨迹及已有推荐保持原证据；新建独立排队任务，并将来源任务、操作者、原因及消息版本写入重试台账、追加轨迹和管理审计。

重试与Telegram接收使用同一逻辑消息互斥锁；等待编辑提交后再次检查最新版本。来源、作者与信任映射加共享锁，阻止信任变更在验证与入队之间穿过。媒体必须ready、原文或图片必须存在、消息不得删除或过时，有当前事件时还须该事件当前有效。

同一逻辑消息的任何版本存在已接受推荐时，重试返回 `accepted_signals_are_immutable`，包括后来撤回的推荐。人工复核历史应走未来只读评估流程，不能用重试改变已接受历史或再次触发订单。

同时活跃任务检查与数据库部分唯一索引保证同一消息版本只有一个 queued/running/retry 任务。相同幂等键、操作者和请求内容重放返回同一新任务；改变原因或来源任务返回409。不同幂等键并发仅能成功一次。审计、轨迹或台账写入失败，整个入队事务回滚。接口本身不创建订单、不使用用户账户、不调用模型。

新增第九次增量迁移保存重试台账及查询索引；迁移遇到历史重复活跃任务会失败，不自动删除或覆盖旧任务。此类情况应先记录现状并制定人工核对方案。

## 标注与真实准确率的后续设计

只读评估集应绑定原消息版本与内容哈希、原图哈希、审核配置版本、系统赛事/盘口证据以及人工标注者。标签分别记录推荐项数量、赛前/滚球、比赛、玩法、期间、盘口线、方向、无法判断原因及复核状态；不得以模型自由文字充当正确标签。推荐意图和实际收益分开评估，划分样本时按消息及专家防止重复泄漏。

本阶段没有真实标注集，不生成准确率、召回率或盈利数字；该设计尚未建立持久化标注功能。网页操作、真实来源和真实模型质量应分别验收后更新状态。
