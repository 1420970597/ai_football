# 盘口上传按比赛隔离的有限异步并发

更新时间：2026-11-09 00:35 UTC。状态：研究完成、设计已记录，尚未修改业务实现或发布。

- 目标：减少互不重叠比赛之间无必要的 HTTP 上传排队；同比赛、共享源编号、未知身份与相交多比赛批次继续互斥。保留用户实盘许可，不能把此优化称作端到端三秒达标。
- 责任目录：services/collector、tests、docs；不修改 executor、API 校验、模型、共享网关、用户设置或现有数据。
- 前置依赖：API f480949 预检优化已通过 E1950 单服务发布；E1960 发布后完整窗口与 E1940 一般监控持续。新增 collector 候选独立冻结、验证与发布，不能把 API 验收当作 collector 验收。
- 当前证据：E1931 实际 410 次上传全部 HTTP200；锁等待 P95 2,756.5ms，HTTP P50 2,070.9ms，总耗时 P95 4,884.3ms。代码只用一个全局 UploadGate；完整批次、WS 和精确刷新均共享。API 已按 source_id 排序父行锁，报价单调更新且收盘/缺失由真实完整快照处理。该证据不区分 WS 与轮询，不声称所有排队可消除。
- 缺口：尚无候选并发正确性、资源峰值、取消/超时、优先公平性与真实效果证据；同比赛热点仍须等待，提供方及跨区域往返仍可能超过预算。
- 设计决策：扩展原 UploadGate，默认仍一个槽，collector 明确采用两个槽。每个批次一次性声明全部稳定 fixture id 与 source_id 键；任何缺失身份使用全局屏障。原子分配全部键，无逐键持有等待；相交批次互斥，不重叠批次最多两个请求。相同优先级等待队列中不得越过存在交集的早期请求；允许跳过被其他比赛占用的请求以利用空槽。沿用最多连续两个精确/WS 优先请求的正常任务公平规则；只对可运行请求选择，取消、异常与关闭必须释放对应租约，不释放别人的槽。
- 实现动作：先增加行为契约并在旧实现复现无键化并发失败；实现原 gate 的有界租约与按批次占用，明确校验回执并更新已送达证据位于同一租约内；实际 HTTP 未知结果先失效原证据，不因并发记回旧快照。保持原消息接收、盘口版本、完整快照关闭、刷新后重检和资金逻辑。
- 验收场景：互异比赛可同时进入 Mock HTTP、峰值始终二；同 id/同 source_id/部分交集严格互斥，缺身份全局串行；正常 FIFO 对相交批次成立，精确优先有上限；排队与已转移所有权的取消不泄露槽，退出时等待者取消；未知结果和非法回执不留下新送达证据；原采集生命周期、WS、精确刷新、快照、乱序、关闭与所有完整套件仍通过。随后固定资源 Docker 镜像、源码核对、仅远程 collector 更新与完整三十分钟自然观察；后续真实投注仍由用户现有选择决定，不作资金测试。
- 失败处理：保留旧实现失败与新候选退出码；行为不等价则不部署。超时、取消或资源退化不能通过扩大时间/队列/服务资源掩盖；必要时仅回退 collector 镜像，不回滚数据、模型或实盘配置。原图/官方消息核对及盘口 freshness 分别记录，不把总库新鲜度或未支持视频算作通过。
