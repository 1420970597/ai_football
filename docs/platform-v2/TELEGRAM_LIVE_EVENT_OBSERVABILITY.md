# Telegram Live Event Observability

Status: design recorded; implementation and 100 focused Docker tests pass. Candidate image, collector deployment and a fresh 1800-second observation are pending. This work adds diagnostic evidence and does not claim to fix the external Hermes provider outage.

| Field | Evidence and decision |
| --- | --- |
| Goal | Identify whether new Telegram messages reach the live callback promptly, are staged, are deferred, or fall through to periodic history recovery; surface the actual bounded source lease failure category. |
| Responsibility | `services/collector/telegram.py`, `services/collector/worker.py`, focused collector tests, and collector-only deployment. |
| Prerequisites | E190a review workers remain active. The configured Hermes model route stays unchanged. Do not write message text, sender IDs, chat IDs, credentials, or media into diagnostics. |
| Current evidence | Watch-05 ran 1803.0 seconds / 55 samples. It saw 15 ready real-time messages posted during the window; all current jobs were retryable provider failures and none had a review receipt. Post-to-event persistence averaged 7.38 seconds, P95 16.11 seconds, maximum 17.57 seconds; 1 of 15 was within 3 seconds. Telegram health intermittently reported `lease_deferred` and `reconciliation_deferred` while all six source leases remained active under one owner. Existing `/status` does not expose live callback counts, and the collector health mapping drops `lease_error`, so current evidence cannot distinguish missed event callbacks from Telegram update delivery delay or name the lease failure cause. |
| Gap | Real-time messages are reaching persistent storage and jobs, but the current health response cannot show which receive path handled them. The worker reports only the lease state despite the collector retaining a bounded `lease_error` category. |
| Decision | Add in-memory aggregate counters for live callbacks received, staged, deferred and unmapped source, plus timestamps and the exception class for the last deferred callback. Expose only those counters in the authenticated internal Telegram status response. Prefer `lease_error` when building a source error summary. Emit no content, platform IDs, source IDs or credentials. Keep counters process-local and reset them on restart. |
| Actions | Update the collector status payload and lease error summary; add tests for success, unmapped source, deferred callback and failure-category precedence. Build and test in Docker; deploy only the collector after current checks pass; start a new 1800-second observation after activation and correlate the aggregate callback counters with newly posted database rows. |
| Acceptance scenes | A staged live callback increments received and staged counters; an event for an unmapped source increments received and unmapped counters without disclosing the source ID; a failed staging call increments deferred and exposes only the exception class; lease health reports `TimeoutError` or the actual bounded lease exception instead of the generic `lease_deferred` state. |
| Failure handling | If the diagnostic counters do not move for new real-time messages while database rows arrive through recovery, investigate handler registration, source key matching, and Telethon update delivery before changing poll cadence. If the failure cause is a slow or unavailable API, keep source leases and data intact; do not extend lease ownership or discard events to hide the condition. Hermes provider failures remain retryable and separate from Telegram receipt evidence. |
