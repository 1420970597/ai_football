# Telegram 来源限时与旧消息复核验收

更新时间：2026-10-27。范围：只修改采集服务 Telegram 实现、新增独立调度测试。本轮不修改 API、模型框架、其他采集协议、全局任务状态或生产数据；不发起真实上游请求，不执行登录、清理或生产故障注入。

## 已确认的原因

原实现对每来源先回补新消息，再向后台领取最多 50 个旧事件，逐事件串行 `get_messages`。后台在返回旧事件前已经把它们的复核时间推进：近两日事件约 5 分钟，旧事件约 6 小时。单次 Telegram RPC 没有截止，三个来源占满三个并发槽后，第四来源无法开始；多个慢 RPC 可跨过后台 90 秒租约和采集循环 120 秒总截止。历史扫描原有的 2 秒软时间片只有在完成一个消息后才检查，无法中止一个不返回的 RPC。

本轮是依据代码路径修复上述机制，不将真实运行中的所有 Timeout 都归因为它；媒体传输原本有独立批次预算，仍可能因真实网络、S3 或后台失败而延后。后续部署后的真实采样由主线验证。

## 实现与约束

| 边界 | 默认值与语义 |
| --- | --- |
| 来源历史硬截止 | 每来源 25 秒，包含现有历史回补与目录刷新；只影响该来源，不让整个 `sync_once` 失败 |
| 历史软时间片 | 既有每片最多 25 条或 2 秒保留；无限历史仍从远端高水位逐片继续 |
| 旧事件领取 | 每来源每次最多 10 个逻辑事件；当前片未完成前不再调用 `observed` |
| 旧消息复核总预算 | 每来源每轮 10 秒；实体解析与每个取消息 RPC 分别最多 3 秒 |
| 批量查询 | 当前片全部成员编号去重，每次最多 100 个；先确认所有编号批次返回，再根据完整返回判断删除或编辑 |
| 失败与取消 | 未成功持久化的事件不从待复核队列弹出；超时只返回 `deferred`，不生成删除事实 |
| 来源公平 | 保留三来源并发；每个慢来源受自身历史及复核预算约束，其他来源继续推进 |
| 末尾续租 | 各来源结束后、独立媒体批次之前，用既有来源锁和后台 claim 做最多 3 秒续租；失败显式 `lease_deferred` |
| 媒体与锁 | 原有下载在来源锁外、提交前续租与版本检查保持；媒体批次仍最多 30 秒 |
| 孤儿盘点 | 单次收尾最多 5 秒；超时显示延后，不拖住下一同步周期 |

时间边界均为命名常量，未引入秘密或新环境配置。来源状态增加 `reconciliation_deferred` 和 `lease_deferred`，保留原历史状态、已核对数量、未完成数量或错误类别；既有工作器将非成功来源作为降级呈现，不能因为总进程仍连接而假报所有来源正常。

四来源在全都占满最坏来源预算时，来源两波最多约 70 秒，末尾续租两波约 6 秒、媒体 30 秒和盘点 5 秒合计约 111 秒。此为预算推导而非测得生产延迟，不包含连接和额外调度开销，且更多来源仍可能触发既有 120 秒外层截止；不以该推导声称任何规模都能一轮完成。没有新增无限后台任务或不受控并发。

## 数据与恢复

1. 新消息只有后端持久化确认后才推进高水位。若后端已保存但返回前超时，下一次或重启后从未推进的高水位重新送入，沿原版本键幂等；不把请求超时当保存成功。
2. 当前已领取旧片保存在采集进程的有限待复核队列（每启用来源最多当前 10 个逻辑事件）。RPC 失败、后端写失败或任务取消保留未完成项，同进程下轮优先恢复该片，不再领取新片。
3. 禁用来源或会话身份改变时，清除其本地待复核片，不在新授权下继续使用旧领取状态；远端原始事件与计划不删除。
4. **后台旧事件尚无领取确认协议。** 若进程重启、身份变更，或领取 HTTP 在后台提交后响应丢失，本地待复核片无法立即重建。原始事件仍持久，下次 `next_check_at` 到期可重新被选择：近两日约 5 分钟、旧事件约 6 小时，再加队列积压与正常轮询等待。这不是无条件时延 SLA，持续故障可更久；本轮不宣称重启后立即复核全部旧编辑或删除。
5. 将来如需跨进程立即恢复，需单独设计后台短领取租约及确认/归还协议，并以事件版本和所有者校验；本轮没有扩大修改到 API 或假造持久确认。

## 隔离验收

新测试调用真实采集调度方法，以受控客户端与后端模型模拟 RPC、持久化失败和取消；不只是测分类。

| 新场景 | 关键断言 |
| --- | --- |
| 正常批量与相册重复成员 | 10 逻辑事件只有一个去重取消息 RPC；每次提交前重新确认租约 |
| RPC 挂起后恢复 | 及时返回 deferred、队列保持、没有删除；下轮不重复领取，完整持久化一次 |
| 取消再入 | CancelledError 正确传播、来源锁释放、未核对片保留；恢复后成功一次 |
| 后一编号批次失败 | 100+1 编号第二批挂起，前一空返回不得提前生成删除 |
| 四来源公平 | 前三来源挂起时第四来源仍成功，四者历史高水位均推进；各锁释放 |
| 高水位及重启 | event 已持久但响应挂起，历史截止不推进 checkpoint；新 Collector 实例重送同事件幂等后才推进 |
| 续租故障 | 一个来源最后续租失败显式降级，另一个仍成功；不抹掉已持久高水位 |
| 后台持久失败 | 原文写失败不弹队列、下轮保留完整正文成功，observed 不重复调度 |
| 无历史截断 | 23 个已存在事件按 10/10/3 轮转全部复核，不把 10 当总上限 |
| FloodWait | 只延后受影响来源，待复核片保留，到期后恢复且不重新领取 |
