领取与租约续期共用 `platform-v2-review-fair-scheduler`。不能先保持此锁再等待在途审核完成：这会阻止续期，最终制造LeaseLost。E163交接已暴露该错误，原失败记录保留，不能以active=0声称自然完成。

项目入口 `infra/remote/review_handoff.py` 只用于发布，不是业务服务。使用Docker内现有工作器依赖和最小角色配置，通过标准输入执行，无需修改运行中的服务代码：

```sh
docker exec -i ai-football-v2-review-worker-1 python - \
  --release-file /tmp/unique-task-release < infra/remote/review_handoff.py
```

操作者须在独立可观察会话运行，使用本次任务从未存在的 `/tmp` 标记名。脚本尝试获取调度锁；若有活动租约立即解锁并等待，允许续期与正常处理继续。最多等待600秒，持续不空闲则退出1，不能停止业务来凑空闲。只有在持锁状态查明active=0后才输出 `idle_gate_held`，此时新领取不能开始。持锁最多180秒，防止无期限阻断。

只有确认上述事件、门禁进程仍活着且锁仍存在后才允许更换目标API。门禁应位于本次不更换的容器。API健康、源码/镜像身份核对及部署模块检查完成后，在同一门禁容器创建唯一释放标记。必须取得脚本 `gate_released` 且退出0证据；超时、断线或非零退出均为交接失败，不能继续声称无中断。此工具不会重建任何服务、修改业务行、生成订单或清理数据。门禁结束之后仍须核对交接段Telegram消息和审核结果。
