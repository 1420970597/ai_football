# 专家输单反馈与新推荐分离

更新时间：2026-11-09。状态：研究中，生产未更改。

- 目标：避免将“捐”等输单反馈附带旧盘口图重新解释成新推荐，同时保留同一消息真正新增的比赛、追线或反向选择。
- 责任目录：integrations/hermes 的项目中文技能、tests 与 docs；不得以业务关键词黑名单替代 Hermes 理解，不更换用户指定模型、提供方、密钥或共享网关。
- 前置依赖：E1960及E2010实际原文、授权原图、审核回执；在自有隔离回放环境使用固定 Hermes 与指定真实模型，所有数据库写入仅到具名临时库，无账户/投注工具。
- 当前证据：E2010别名18正文“捐”，附原别名4相同盘口图，实际工具因比赛完场未录入；模型仍把旧选项当新意图，不能将零信号视作语义正确。别名10/12/23的“收米”与较早注单、较晚比分被正确归为反馈，正向别名4/5/6/17/19/22及空正文六图相册需继续保留。
- 缺口：现技能明确收米等赢单反馈，未明确输单口语；缺真实模型对输单、引用旧图及混合新推荐的对照证据。
- 设计决策：只澄清项目技能中的语义规则，不在应用中遇词跳过，不缓存否定意图；按本场证据区分输赢反馈与新增指令，独立新场、追线、反向等仍走现有唯一赛事/有效盘口核验。
- 实现动作：先在私有冻结副本试验原图与混合场景；核对真实工具调用和结论，而非只校验提示词字符串；确认不抑制新增推荐后才进入可审查源码改动、固定框架回归及项目内发布。与十秒性能分开记录，模型HTTP整轮耗时包含工具，不能冒称纯生成耗时。
- 验收场景：实际“捐”旧图不搜盘不录入；其他赢/输反馈无新增；同词附新增比赛/盘口仍核验；空正文已选盘口仍核验；相册多场不误归为整体反馈；框架工具白名单与用户交易开关保持不变。
- 失败处理：保留误分类与工具轨迹；不以完场、停盘导致零信号掩盖意图错误，不做历史补投，不修改收益或原文。任何有新增意图被压制则候选不得发布。
