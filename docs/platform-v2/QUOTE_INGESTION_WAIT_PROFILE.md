# 精确盘口刷新写入等待研究

更新时间：2026-11-07 10:36 UTC。状态：研究中；未修改业务实现。

- 目标：区分远端数据库往返、写入争用与完整框架模型轮次，针对真实关键路径决定下一次改动，不以接收时间替代源报价时间。
- 责任目录：API盘口入库与collector精准刷新职责；本阶段仅受保护运行目录内的只读诊断和docs证据。
- 前置依赖：E596现有API/collector保持运行；E628仅MCP/技能发布通过，E631/632自然窗口运行；不得中断自然监控或改变交易许可。
- 当前证据：E627部署后14次自然精准刷新全部written，source_ms中位1815.5、ingestion_ms中位2386.1、总中位4134.9，最大总6718.2毫秒。无同值省写命中。现有API已是批量fixture/quote入库，不能未经测量重新实现同一批量机制；全库报价变化时间偏旧也不代表没有完成原生精确观察。
- 缺口：ingestion_ms包含collector到API、连接池及事务/远端SQL，现有总计时不能归因于某一项。数据库当前锁和空往返尚无同窗口证据。
- 设计决策：E637以独立受限容器、独立只读连接和短statement_timeout，在一分钟内13次采样空SELECT往返及当前数据库backend等待类型聚合，不读取SQL正文/参数/密钥，不EXPLAIN ANALYZE任何写语句；表维护计数仅前后各一次。与自然刷新时间比较，只能得出采样范围内的结论，未捕获写入时不称已排除争用。
- 实现动作：先运行上述有界只读诊断并保留原退出码，再从当前已有upsert/事务路径定位可测的缺口。只有因果证据和明确失败行为后才制定局部实现；不扩大刷新并发、不降低分页/时效/期间/精确绑定校验，不修改其他项目或共享网关。
- 验收场景：生产信号/订单/许可零诊断写入；采样次数、窗口、连接与语句时限可核验；统计不泄露SQL/参数。后续改动须有独立行为测试、同源完整回归和自然联调，单次首轮模型请求或数据库往返不能冒充端到端3秒。
- 失败处理：诊断权限或超时错误原样记类别和退出码，停止对应诊断、不临时提升数据库权限。保留原始失败，已有业务采集与审核继续。
