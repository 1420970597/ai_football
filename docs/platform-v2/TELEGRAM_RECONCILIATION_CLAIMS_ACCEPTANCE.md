# Telegram 旧消息持久领取确认验收

更新时间：2026-10-27。状态：代码已写、定向隔离验证通过、已冻结；未迁移生产、未发真实 Telegram 请求、未提交 Git。此包修复此前 TELEGRAM_SOURCE_SCHEDULING_ACCEPTANCE 所明确保留的跨进程确认缺口，既有来源时间预算、媒体锁外处理和原始记录保留政策继续有效。

## 原因与目标

旧 observed 在返回事件前推进 next_check_at。读取请求回包丢失或采集器重启后，虽然原始事件仍在，旧编辑或删除仍可能等待旧事件约6小时的复核周期。单进程待复核列表只能改善本进程重试，无法证明跨进程恢复。

本包将“领取”“检查结果持久化”“确认推进复核计划”分开。所有领取信息保存远端事件行，任何 RPC 超时或取消都不是消息删除证据；只有完整取回当前片全部编号批次后，才生成删除或编辑提交。

## 协议和一致性

| 操作 | 约束和结果 |
| --- | --- |
| 升级协议协商 | observed请求必须显式发送严格Literal reconciliation_protocol=claim-ack-v1，无默认值。旧采集器缺字段或任何不同类型/版本在进入路由前422，不取得claim，不续来源租约，不改变due；不自动降级回旧协议 |
| 领取 observed | 先验证启用来源与90秒来源所有者租约；按 due/id 有界读取并 SKIP LOCKED；每事件随机 claim_id、owner、原始版本与30秒租约。**不改变 next_check_at** |
| 检查提交 events | 增加可选 reconciliation 引用，仅旧消息复核使用。来源行锁之后在同事务锁原事件、验证 owner/source/event/version/token/当前状态/短租约，以及原事件逻辑编号和成员范围 |
| 事务应用标记 | 原始请求规范内容的 SHA-256 与检查应用时间随原有编辑/删除/入队事务提交；任何后续校验失败均回滚标记。凭据与原请求体不另存 |
| 重复请求 | 相同 claim+相同原始内容已提交时返回 reconciled；不同内容409，不能用重复请求覆盖首次事实 |
| 确认 observed/ack | 重新验证来源租约及原事件 claim，要求检查提交已应用且短租约仍有效。确认后才将当前事件 next_check_at 推进：源版本近2日5分钟，否则6小时；已确认的同token幂等返回，不再次推迟时间 |
| 已修订/删除 | 合法检查事务可能把原事件变非当前，仍可确认该已提交原 claim；不修改新版本的复核时间，不改变新版本/媒体恢复任务 |
| 丢回包 | event 已保存但回包丢失，进程内保留首次完整请求并原样重送；不重新生成删除时刻或版本。ack已保存但回包丢失，仅重复ack，不依赖第二次TG请求 |
| 进程重启/过期 | 未确认事件仍due；30秒领取过期后可由新尝试重领，新token使旧尝试拒绝。来源接管还必须先取得90秒来源租约；不能把30秒称为所有情形SLA |

采集器每来源仍最多保留当前10个逻辑事件和有限首次提交副本；过期本地引用舍弃后回到远端有界领取。新会话/来源停用仍清除本地队列，远端事实不删除。RPC总截止、取消和失败不提前确认，也不伪造删除。没有自动无限重试、没有释放事务原有来源/消息一致性锁。

## 变更范围

- 增量019仅给已有事件表加领取、应用摘要及确认列和 due 索引；旧列、内容及 next_check_at 完全保留；新列默认NULL。未改已应用迁移，没有新预置业务行。

## 严格协议追加验收（最终冻结）

最后只读反例审查发现：新API若继续接受旧observed请求，旧collector可忽略返回claim后按旧events路径提交，破坏预期升级边界。因此追加必填且无默认的严格Literal协议字段，并令collector显式发送。此修复没有更改019迁移、领取领域模块或采集调度算法。

新增2项真实PG测试：

1. 缺字段（旧请求）、legacy、未来版本、大小写变体、null、整数、布尔分别422；逐次比较完整事件行及完整checkpoint行均与请求前一致，证明未领取、不改变due且未续来源租约；其后正确协议可正常领取。
2. 已存在active claim时，缺/错协议仍422且完整事件/来源行不变；原合法claim继续提交确认成功。

新增2项httpx传输测试：真实TelegramBackend序列化请求，精确检查方法、路径、源、owner、limit及claim-ack-v1；服务422时仅请求一次，不删除协议字段或自动降级再发。既有真实Collector+API+临时PG测试也经该实际backend发送新字段。
