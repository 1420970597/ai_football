# 系统对阵文字声明必须有绑定证据

更新时间：2026-11-09 17:20 UTC。状态：最小修复与针对性隔离验证通过，实际工作器图文链待验收，未发布。

- 目标：模型以“对应系统比赛为/对应的系统对阵是”陈述双方，却未真正唯一解析时，不将该轮标记为审核校验通过。
- 责任目录：services/api审核完成的具名声明提取、tests真实PostgreSQL/完成事务与续审回归、docs证据；不改队名等价、搜索范围、盘口、价格或用户交易范围。
- 前置依赖：E2416空正文原图回放、E2423只读原轨迹复核。实际未绑定，模型声称已识别完场；named_claim输入仅包含没有队名的16字开头，原completion_issues返回空。
- 当前证据：E2423原生0，actual_binding_count=0、completion_issues={}、explicit_mentioned_ids=0；不是已经匹配成功，也不能靠零信号遮盖错误说明。
- 缺口：已有提取器覆盖“已匹配/已识别”，没有覆盖后文明确“对应系统比赛为”的完整双方声明，导致现有SQL的同一子句、同任务和当前尝试绑定检查未被触发。
- 设计决策：仅扩展已有具名声明语法，保留每条声明边界；“无法确认/尚未确定/可能为”不作为肯定匹配。声明只触发负向校验与原有有界续审，绝不创建或放行绑定、猜测球队或盘口。最终事务沿用相同提取，不能由后续无信息文本清掉先前肯定声明。
- 实现动作：先在原5a3e16c冻结代码复现无编号系统对阵、明确否定、真实绑定和最终事务；再局部修改提取器，重跑命名/阶段/候选排除/续审/真实事务及全量隔离；固定Hermes与原图再证明工具证据，不只检查字符串。
- 验收场景：无编号明确对阵仍需实际绑定，另一attempt不能冒用；已绑定仅一轮结束；否定/推测不会强制匹配；不同声明队名不交叉拼接；原逐项接受和无效盘仍按原规则；无绑定时最终completion_verified=false、无信号/订单。
- 失败处理：保留实际失败；续审耗时计入真实总耗时，不冒充十秒。任何误绑定、负向误报或事务回归失败则不发布，保留现有生产及用户模式/实盘许可。
