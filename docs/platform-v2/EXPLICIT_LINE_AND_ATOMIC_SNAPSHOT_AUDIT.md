# 显式盘口线与有界完整报价快照审计

日期：2026-10-27。工作包：P09-03，以及本轮真实采集暴露的单场五百报价上限问题。状态：代码与隔离验证通过；本文不代替真实迁移、协调部署、浏览器验收或正式发布。

## 已确认根因

1. 旧 API 在请求没有盘口线时自动填零；数据库三类表也有零默认值。独赢的“不适用盘口线”、亚洲让球零线及消息缺失线因此无法区分。结算函数还在缺线时再次填零。
2. 单场完整快照的旧请求只接受五百条报价。生产故障证据由主线保存；本工作包只复用其故障结论，没有额外请求比赛、登录或交易接口。
3. 将完整快照拆成多次 HTTP 并在最后请求关闭旧盘，会引入前片成功后片失败的部分写入风险。因此沿用同一入库接口、同一数据库事务，只增加有界分片表示。

## 契约与责任边界

- winner 的新规范输出为显式 line: null，仅兼容旧的显式数字零；非零独赢线拒绝。请求省略整个线字段拒绝。让球、大小及尚未支持的数字盘口必须显式有限线，数字零合法。既有一千绝对值预算与数据库三位小数契约保持一致。
- 普通 markets 保留至多五百报价。新 market_chunks 为一至四块，每块一至五百报价；顶层 market_chunk_count、market_quote_count 必须与实际块数及总数相等。出现分片时禁止同时提交 markets 键，即使其为空。
- 整批所有比赛报价总数至多两千。同场引用键由比赛内玩法、期间、规范线及选项决定，重复引用在写前拒绝。独赢旧零与新空值是同一引用。
- 实际请求流最多四 MiB，读取总截止十秒，先限制字节再解析 JSON。内部采集直接访问业务 API；公开网页网关不暴露内部路由，其一 MiB公开请求限制无需扩大。
- 完整分片只在同一请求内展平，沿用同一数据库事务完成比赛、所有报价和缺盘关闭。缺片、超限、重复、时间冲突以及数据库后段错误不提交半份完整快照。markets_complete 仍只存在于比赛顶层；不把部分增量标为全量。

本包变更范围：API 的内部契约、入库、审核、订单授权、统计和结算；采集协议解析；执行器原生预检；质量评估格式；增量结构迁移及专项测试。采集分片编码、工作器与推送缓存由同轮另一工作包独立实现，本包没有修改这些运行模块。

## 历史兼容与迁移门禁

增量迁移 018 没有修改 017，没有批量回写当前报价、推荐、证据、订单或不可变计算。迁移先阻断不兼容旧线和语义重复键，再取消三类表的零默认并允许空线。写约束经过现存行验证，不用未验证约束掩盖旧行未来更新失败。

当前报价及推荐唯一索引仍使用既有名称，通过 COALESCE(line,0) 表达式保证独赢新空值与旧零不会生成双引用。数字玩法禁止空线，因此该表达式不会将缺失让球线误认为零线。当前报价在收到实际新报价时可更新线表示并保留原报价编号；不可变推荐及证据保留旧值。审核幂等查询、订单引用和收益证据校验只对独赢允许零与空值等价；新空线证据必须携带明确的独赢类别。

旧独赢零推荐重建仍序列化原零输入，保留原算法编号及不可变计算；新独赢空值计算保留 JSON 空值。没有把历史计算中的零批量替换为空值。

发布顺序必须协调。新代码冲突目标与旧唯一索引结构不兼容。主线须先完成迁移前备份和恢复目录校验，暂停本项目写入工作、排空租约，在同一维护阶段执行迁移并替换业务 API、审核、采集及执行器；确认结构一致后再放行写入。不得让旧 API 在新表达式索引上继续提交，也不得让新 API 指向未迁移数据库。真实执行由主代理统一处理，本包没有执行真实迁移或重建生产服务。
