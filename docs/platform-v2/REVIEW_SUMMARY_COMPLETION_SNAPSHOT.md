# 回执快照包含未完成分页证据

更新时间2026-11-06 04:58 UTC。状态设计已记录；工作包E403，责任目录services/api/app与tests，依赖E399既有领取、当前尝试/trace事务锁及现有回执读取合同。

目标是减少无系统比赛编号说明的结论事务远端读取，不改变模型、信任来源、推荐价格或结算。E398四条无推荐新帖均有完整回执，结论后段仍有多次约235毫秒远端往返；不能以本工作包声称达到3秒。当前read_summary_evidence取得模型所有部分/最终内容后，record_summary总是再发completion_issues查询，即使没有任何模型比赛编号，仍单独重复查询未完成分页。

设计：提取原未完成分页CTE用于完整校验与回执快照，按同一job/attempt在原一次快照读取中返回未完分页数量、原scope、准确next cursor及最多100项。Python仍按现有规则扫描全部部分/最终模型内容。只在没有任何比赛编号提及时使用该同次快照的分页检查；只要存在编号，继续调用原完整completion_issues验证全部未绑定编号及分页。不会因为模型声称完成或completion_verified=true跳过服务端证据。

实现动作：共享固定SQL片段，扩展内部不可变快照数据；保留read_summary_evidence单次读取；将无编号回执总读取2变1，有编号保持2。验收覆盖零内容/无意图、不完整分页不能通过、scope及cursor保持、旧attempt隔离、部分轮提及不能被最终文字掩盖、100项截断与真实总数、编号正则边界、并发trace等待后可见和事务回滚。代码冻结后临时具名PostgreSQL定向及干净完整套，候选实载后才能生效；E401观察中不改运行代码。

失败处理：任一分页/绑定/回滚合同失败停止部署、保持E399生产工作器，保留失败证据并修复重跑；不删校验、不改模型摘要、不修改历史回执或生产记录。
