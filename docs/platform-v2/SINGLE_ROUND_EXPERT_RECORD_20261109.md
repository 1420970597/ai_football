# 明确大小球意图的一轮工具录入

目标：对来源双方、玩法、期间、方向及数字线都明确的新增大小球推荐，在同一次Hermes工具调用内复用原搜索、绑定、读盘和录入，减少一次“读到报价→再生成录入参数”的模型往返。仍以原生record_expert_signals事务接受为准，不扩大投注许可或跳过价格/来源检查。

责任目录：services/hermes-mcp、integrations/hermes、tests、docs。前置依赖：TOTAL_SOURCE_INTENT_20261109隔离验证通过；已部署数据库邻近受限API；四原工具、连续分页、当前任务/attempt及不可变价格契约。

当前证据：E2569真实原图正例使用合并搜索读盘后仍需第二次模型调用提交，五例总耗时11.796–26.845秒；E2640新生产七条非推荐无MCP调用，模型/框架本身仍约2.823–7.942秒提供方时间。原图期间歧义是正确拒绝，不能为速度接受；仅移除数据库WAN往返不能保证十秒。

缺口：现有search_matches/resolve_match可返回market_result，但即使精确期间、线值与方向只有一个可录入选项，也需模型再次生成相同fixture_id与quote_id。该额外模型轮次可以通过现有原生操作组合消除，不需要新交易工具或第二套比赛匹配实现。

设计决策：在原搜索/消歧工具添加默认关闭的显式record_source_intent和受限evidence_text参数。只允许read_markets=true、明确total和标准期间、原文明示market_query的请求尝试；服务端实际返回的market_filter必须包括相同玩法/期间、明确线值及大/小方向，覆盖完整且恰好一项，报价自身同fixture/玩法/期间/数值/方向、active且can_record=true。否则返回原生读盘证据和明确未录入状态，保持通常的模型核验路径，不选择库存第一项。不为让球/球队进球或未知期间推导原生口径。

实现动作：先覆盖旧代码无此一轮行为的真实MCP协议测试；再在原合并路径内调用既有record_expert_signals，传同review_id/attempt_id及实际已读唯一quote_id，不缓存或改写价格。成功保留market_result和原生record_result；录入失败保留有界完成回执与原生错误，不将读盘成功冒充已录入，不重新开始已完成检索。旧调用默认不写入；分页未完、不唯一/完场、零或多报价、源停用/改版、过期/上下文变化、取消与超时均走原边界。框架与服务白名单仍是原四项审核工具，盘口串行准入/上游预算不变。
