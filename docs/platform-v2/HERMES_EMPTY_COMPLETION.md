# E424 Hermes 无回复不得封口

更新时间：2026-11-06 08:16 UTC。状态：代码已写，定向隔离106项通过，完整冻结及真实部署待验。

- 目标：框架无回复提示不得作为模型审核结论关闭任务；恢复后可由既有调度器继续审核。
- 责任目录：`services/api/`、`tests/`；不修改固定 Hermes 镜像或模型配置。
- 前置依赖：当前模型与固定 Hermes v0.22.5；既有 provider_transient 持久退避、租约和审核回执机制。
- 当前证据：E417 有5条 finish_reason=stop 返回框架 No reply/empty_response 模板，其中一条原文包含3项推荐；现有代码把它们存为普通 unresolved。框架模板从运行镜像 agent/turn_explainers.py、locales/en.yaml 和 turn_finalizer.py 只读核验。
- 缺口：上游恢复后这些任务不会自动重试；HTTP200/stop 不能证明模型生成成功。
- 设计决策：只识别空结果及固定版本已核验的完整无回复模板；模型占位限定本次请求、响应模型或框架默认名称。正文包含或引用这些文字时不误判。异常使用既有脱敏 HermesProviderUnavailable，不保存伪模型或系统完成回执，不新增热请求。
- 实现动作：在客户端结果形状归一后、构造成功 summary 前检查；沿用 provider_transient 退避；用标准管理员补审入口恢复确认误收的当前版本，旧证据和已接受推荐保留。
- 验收场景：HTTP200/stop 的字符串、分段文本、空白、固定重试耗尽及待工具提示均可重试；正常无推荐中文、引用模板和不同模型文字仍为普通结果；真实HTTP模拟贯通工作器后任务为retry、失败类别正确、无虚假双回执，下一次成功可完成。
- 失败处理：任何正常文本误判或假完成回归失败均停止部署，修复后原场景重跑。干净完整套、同源镜像、自然空闲切换、真实补审和新30分钟监控完成后才升级状态。
