# 第二代平台架构与实施取舍

更新日期：2026-10-26。架构已形成开发候选，356项后端、24项网页Mock、11项真实API隔离浏览器及17项Android验证已记录；真实提供方、远端生产存储、设备UI与正式发布仍未验收。当前新增公平调度、TG目录修复、日限额时区及无障碍审计分别冻结验证，不把设计或已有代码当成生产运行事实。

## 节点与职责

本机 Docker 运行网页入口、业务 API、审核工作器、项目 MCP 和 Hermes。远端 VPS 保存数据库、原文媒体与业务证据。采集、续期及订单执行先检查现有远端部署，再测出口、时延和安全边界决定位置；本地采集编排仅是开发草案，未决定生产迁回。

```mermaid

    A[Android 配对客户端] --> W

    R[审核工作器] -->|领取租约| DB

    H --> M[项目 MCP]
    M -->|当前尝试与服务鉴权| API
    O[独立订单执行器] -->|本人许可与状态机| U[用户自己的乐鱼账户]
    O -->|受限账户与订单接口| API
```

| 模块 | 输入及输出 | 关键约束 |
| --- | --- | --- |
| 网页和 Android | 页面请求、筛选及本人操作 → 展示及明确状态 | 不持有供应商秘密，不由客户端决定权限 |
| 业务 API | 用户或受限服务请求 → 校验后的数据与写入 | 身份、权益、对象归属、幂等及审计 |
| 采集 | 授权上游消息和报价 → 规范化事实 | 原始标识、真实时间、检查点，不做推荐或下注 |
| 审核工作器 | 消息版本 → Hermes 审核及轨迹 | 租约、尝试隔离、并发、超时及死信 |
| Hermes | 原文和图像 → 受限工具调用及简体中文说明 | 不可信消息不能改权限，供应商调用只在框架内 |
| MCP | 当前尝试的搜索和盘口 → 工具事实及接受结果 | 无 SQL、秘密、终端或交易能力 |
| 结算与订单 | 不可变推荐/成交证据 → 版本化结算 | 专家一单位账与实盘账分开 |

## 消息到推荐的时序

```mermaid
sequenceDiagram
    participant T as Telegram
    participant C as 采集
    participant API as 业务校验
    participant D as 远端数据层
    participant R as 审核工作器
    participant H as Hermes
    participant M as MCP
    T->>C: 原文、作者、回复与媒体
    C->>D: 流式上传受限媒体
    C->>API: 幂等导入消息版本及媒体状态
    API->>D: 原文及审核入队事务
    R->>D: 领取当前尝试和租约
    R->>H: 结构化文字图片与任务上下文
    H->>M: 连续搜索赛前及滚球所有候选页
    M->>API: 校验查询游标、尝试及搜索范围
    API->>D: 查询投影并记录候选和连续页
    H->>M: 唯一比赛的精确盘口读取
    M->>API: 记录该尝试已读取盘口
    H->>M: 提交多项推荐
    M->>API: 逐项复核引用、租约和源时间
    API->>D: 推荐与系统报价证据事务
    API-->>H: 接受标识或未解决原因
    R->>D: 保存轨迹及实际终态
```

MCP 读取的是业务规范化投影，不直接重新采集上游。模型输出不是成功标志：工具必须确认接受，过期尝试不能写入。搜索完整、唯一消歧、实际读盘和最终报价有效是四道独立门槛。

## 关键设计决策与现有缺口

| 决策 | 选择及原因 | 已发现缺口与验证 |
| --- | --- | --- |
| 数据建模 | 当前盘口投影与不可变证据分开，减少IO又能重建推荐和订单 | 单调水位、全量/部分快照、报价证据和合成恢复通过；远端真实保留演练待验 |
| 任务调度 | 使用PostgreSQL事务领用及租约，保持单一事实队列 | 尝试隔离、心跳、死信及幂等重审已验证；跨专家公平调度本轮另验 |
| 匹配 | 键集分页遍历全候选，按双方、联赛和时间唯一判定 | 真实Hermes框架连续105场、唯一消歧和先读盘口通过；真实模型与译名语义仍待验 |
| 身份权益 | 独立管理会话、令牌摘要、权益合并及近期敏感操作重验 | 70项身份生命周期/MFA场景及会员边界通过；生产引导和真实HTTPS设备会话待验 |
| 存储连接 | 独立迁移工作器有版本锁，API启动仅只读校验 | 并发冷启动修复已通过；生产最小权限角色和外部旧结构升级尚未核验 |
| 网页客户端 | 共享视觉令牌，桌面表格和手机单列分别设计 | 24项Mock加11项真实API隔离场景通过；原站私有页、真实S3与完整辅助技术待验 |
| Android | 受限网页容器加HTTPS身份配对，复用同一界面契约 | 17项、Lint及两类开发APK通过并安装；设备UI被模拟器系统异常阻断，正式签名与升级未验 |
| 支付 | 人工真实开通为基础，外部支付为条件适配 | 未选网关不制造支付成功，也不阻断核心专家业务 |
| 续期网络 | 可编辑短期代理只供明确登录请求，其他链路正常出口 | 协议样本与隔离续期互斥/CAS通过；旧有效配置、真实登录出口和只读新鲜度待验 |

性能取舍以[量级基线](PERFORMANCE_BASELINE.md)为准：10k赛事/50k报价下，试验索引明显改善SQL而未稳定改善首页HTTP尾延迟，因此未增加生产索引或缓存中间件。该结果来自0.75核预算与tmpfs，不代表真实磁盘IO。个人日限额按明确时区的自然日统计；历史未知订单仍占开放敞口，时区变更属于本人重新授权。

## 订单状态和资金边界

```mermaid
stateDiagram-v2
    [*] --> 待预检
    待预检 --> 已拒绝: 无许可或报价无效
    待预检 --> 已预留: 账户锁及限额通过
    已预留 --> 提交中: 再次核验
    已预留 --> 已释放: 停止或过期
    提交中 --> 已接受: 明确接单回执
    提交中 --> 已拒绝: 明确拒单
    提交中 --> 结果未知: 超时或回执丢失
    结果未知 --> 核对中: 只查单不重投
    核对中 --> 已接受: 确认接单
    核对中 --> 已拒绝: 确认未接单
    核对中 --> 结果未知: 仍不能确认
    已接受 --> 已结算: 官方结算证据
```

unknown 与 submitting 都占敞口。本人许可绑定账号和策略版本，管理员没有隐式代投权。资金操作只在授权范围执行，开发验收使用无资金协议样本。结算修订追加版本，不覆盖原始报价和回执。

## 数据及秘密

- 业务持久数据与媒体在远端。测试只用具名临时库，不静默回落本地生产存储。
- 旧库不破坏，新结构增量隔离；迁移失败保持未就绪。运行工作器不无条件重复迁移。
- 每服务白名单注入；模型提供方密钥仅交 Hermes。旧会话加密主密钥先核验，不能由新密钥替换。
- 媒体私有访问、内容哈希、字节上限、暂存确认和孤儿回收；数据库备份必须与媒体引用共同恢复。
- 高频旧盘口先统计引用并复现收益，再隔离清理演练；当前没有远端清理授权落地动作。

## 性能验证与阶段放行

先测实际源事件至页面、每页搜索、排队、模型、数据库及对象存储耗时分位，再按部署容量制定预算。不给未经测量的延迟贴精确数字。优化从索引、批量写、缓存期限、连接池和任务合并入手，不能删校验换速度。

按“规划基线 → 比分原文可读 → 专家可核验 → 个人账户可控 → 三端发布”推进。每段保存命令、退出码、冻结源码、样本与局限并及时提交。正式发布还须远端恢复、Android 安装升级及实际镜像和 APK 资产核对；候选构建不等于发布。
