# 审核任务领取一次选择

更新时间2026-11-06 04:30 UTC。状态设计已记录。责任目录services/api/app、tests；E399不改变模型提供方、提示来源、群组信任、历史回放和用户订单。

## 目标、依赖与证据

E393完整窗24次领取中位1.838秒，当前完整领取在历史关闭时仍5次远端语句，加上事务开始/提交。现有排队中位13.520秒、模型中位10.847秒，减少领取一次远端往返只能解决其中一部分，不能承诺整体3秒。依赖已有事务级调度锁、源/专家公平轮转、任务行SKIP LOCKED、来源共享锁、随后独立获取trace锁与独立插入回执。

## 缺口与设计决策

原配对查询及任务选择/轮转查询串行，配对与候选读取可以在同一条SQL内执行。MATERIALIZED选定且锁定一个源/专家，任务仍按原时序/新鲜与老化规则FOR UPDATE SKIP LOCKED；无可锁任务也必须推进该配对轮次并继续有界探测。返回配对但空任务与完全无配对分别处理。调度初始化、激活获取trace锁、trace写入保持各自后续语句，避免锁等待后的同语句快照漏掉先前回执。原资格和重试谓词逐字保留，当前全局并发及专家上限不变。

## 实现与验收

提取受限SQL生成器，配对/候选/公平轮转合并为一次命令，主领取由5至4语句（历史关闭且首次配对命中）。真实临时PG覆盖源/专家/任务锁、同一配对被锁队首、所有任务被锁后推进其他配对、八探测上限及下一次轮转恢复、并发领取和心跳不超额、停用和过期拒绝、trace等待后序号连续、写失败事务回滚；新增并发源停用必须等待已有领取事务的共享锁，随后不得再领取。冻结定向、提交、干净全套与镜像实载核验后才在自然空闲门更新工作器；真实全窗确认分段耗时及无漏任务，不能用查询数或隔离微秒替代业务证据。

## 失败处理

任何资格/公平/锁/回执测试失败停止上线，保持旧运行工作器；保留原失败码并修根因后重跑。不得通过删历史、跳审核、增并发或移除工具/报价重验来达标。E397旧提示冲突另有已持久化模型治理基线依赖，不能直接更改prompt并让所有工作器摘要拒绝；本工作包保持其摘要不变。
