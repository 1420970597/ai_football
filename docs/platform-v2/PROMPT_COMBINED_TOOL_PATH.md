# 系统提示的联动读盘路径一致性

更新时间：2026-11-07 16:15 UTC。状态：研究中，受控首轮对照准备，生产提示未改。

目标：减少原文双方与玩法/期间明确时的额外模型往返。责任目录services/api与tests，前置为已上线MCP search/resolve的read_markets联动及技能完整分页/唯一绑定规则；Hermes固定版本、视觉、四工具白名单与实际模型deepseek-v4.1-flash保持。

当前证据：15:23真实推荐分别调用search、resolve、list和record，两轮总170秒；15:31样本还因上下文及停盘重复读盘。当前最高优先级SYSTEM_PROMPT只要求双方参数，并写“唯一绑定调用list_match_markets”，没有说明复用已附带的market_result；下层技能和工具说明已支持read_markets=true并明确不要重复读盘。该不一致是可核验的提示缺口，但不能据此声称所有重复调用的因果已证实。

设计决策：候选明确双方和玩法期间可读时传team_a/team_b、read_markets=true、market_kind/period；仅完整分页且服务端唯一活动绑定才可复用market_result，其本身是原工具读盘证据。没有该回执则继续原list路径，未唯一/非活动/其他玩法仍独立核验；不传猜测盘口线，不降低录入要求，不比较专家倍率，不改变模型或工具权限。

实现动作：先用当前固定原生transport、完整系统/技能上下文、完整工具schema及三条已有授权图片，对旧/候选仅首轮作交错六次对照；每次调用前按真实领取条件只读检查无当前任务，30秒deadline、max_retries=0、每文件仅一请求。只记录工具调用结构、耗时和累计usage，不执行工具、不创建生产任务或订单，不让历史图片产生当前信号。候选只在受控探针中替换原系统段，真实配置保持。若证据支持再补提示行为及框架契约，经过模型来源与配置版本治理后实施，不写进正在测试的E869冻结源码。

验收场景：三种原文均保留真实双方、项目、phase=all、玩法及期间的正确联合首调用；无凭据不录入、分页未完整不读盘、唯一活动结果才复用，其他情况正常回退；定向与完整固定框架、实际API/worker提示摘要一致，新自然消息再核验轮次及耗时。首轮六样本只证明有限结构行为，不能证明准确率或3秒。失败处理：保留各请求原退出与响应类别，网关400/超时不改格式猜参数或无界重试；结构有退化不部署，继续现网监控。

剩余依赖：E869诊断候选完整回归仍运行，现网b8801c6；E839连续窗口及新推荐语义未完成。本阶段不会用宣传无意图样本代替比赛绑定，亦不把局部往返减少写成全链路达标。
