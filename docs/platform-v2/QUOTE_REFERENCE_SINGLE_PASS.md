# E395 报价引用单次定位

更新时间2026-11-06 04:01 UTC。状态：研究中，未改业务源码或生产。

- 目标/责任：减少实际quote_upsert的冷索引探测和批量写成本；services/api报价入库、tests行为验证、reports对照证据。保持5秒执行预算、全部时钟及身份约束。
- 前置/证据：E320同PID真实DataFileRead至5秒超时、存量UPDATE已生效；E391仍出现同一upsert超时。E395实际运行源码生成SQL只读EXPLAIN actual0（无ANALYZE写语句）发现UPDATE和INSERT反连接各做一遍reference索引查询；1/79输入均两次。当前约333万报价、760MB表/1114MB索引，不能用小热缓存证明生产冷盘。
- 缺口：尚无该新失败同时刻等待类型，不将E320旧IO证据冒充本次根因。单次引用映射是否降低总成本、增加主键探测是否抵消收益，需要原样隔离交替对照。
- 设计决策：研究把incoming和既有引用只连接一次且MATERIALIZED；既有项按稳定id UPDATE，缺失项INSERT并保留ON CONFLICT时钟重验。无删除、无缓存陈旧盘口、无全表读、无预算放宽，不修改信号、报价身份、终态或原数据。固定ID主键定位是可审查候选，不预设优于原实现。
- 实现动作：先在.runtime固定独立草案，不改被测业务源；受限Docker临时PG，以79/2000项、相同/旧/少量变化/全变化/混合/新插入多轮交替EXPLAIN ANALYZE及回滚，记录执行/缓冲/计划。确认收益后才增加局部业务实现和必要行为测试；不成立保留负面研究并继续根因。
- 验收场景：原稳定ID/xmin、混合插入更新、原时钟/完整快照/终态保护、报价读取无阻塞、并发新旧更新、并发插入冲突、null/zero重复拒绝、整批失败回滚。完整冻结通过、同源镜像/配置预检后才自然门部署，旧推荐/报价证据/结算保持，另开1800秒真实观察，不能只凭微基准标记根因修复。
- 失败处理：SQL或行为变化先修根因，保留失败输出，重跑相同测试；性能无优势不发布。生产只读采样最多本项目40后端、无SQL/参数/秘密输出；无复现仍标未复现，不进行全局数据库/其他服务调优。
