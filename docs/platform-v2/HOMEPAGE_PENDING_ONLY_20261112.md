# 首页专家关联仅显示未结算推荐（2026-11-12）

## 工作包

- 目标：按用户最新要求，首页专家关联比赛与盘口只展示未结算记录。
- 责任目录：services/api/app/routes/、tests/、docs/platform-v2/、reports/；页面样式和业务执行不变。
- 前置依赖：网页分支01c4510b；线上API public模块SHA840ae1e1…与该工作树完全相同，主检出模块不同，不能用旧模块覆盖线上性能/过期赛事修复。
- 当前证据：比赛EXISTS筛选和批量推荐摘要共用可见性条件，但未限制outcome；最新网页直接展示服务端expert_signals，故修复应在分页前服务端完成。
- 缺口：全部结算比赛仍占首页名额，混合状态比赛的已结算盘口仍可见。
- 设计决策：专家关联以推荐outcome=pending为未结算事实，不用比赛finished状态代替结算；在比赛EXISTS及摘要LIMIT之前应用同一条件；游标标明pending语义，拒绝沿用旧筛选游标；汇总时若并发结算导致无待结盘口，不返回空比赛壳。全部赛事、详情与专家历史/统计不受影响。
- 实现动作：局部修改公开查询条件与游标范围；增加结算各状态、混合盘口、摘要上限/分页、完场仍待结、结算后刷新与历史保留测试；调整现有浏览器样本，使完场待结不冒充全赢。
- 验收场景：全赢/半赢/全输/半输/走盘/作废推荐均不进首页；混合场次仅pending；分页/游客与会员上限按pending计；已完场但pending仍按当前状态筛选显示；全部赛事与历史保留；真实3003/公网返回零已结算摘要，桌面与手机实际展示一致。
- 失败处理：保留失败和退出码后重跑原场景；失败候选不部署。只使用临时具名数据库，生产仅只读核验；如需恢复，只恢复原API镜像，不回滚业务数据。
