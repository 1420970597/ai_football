## 已实现的实质门禁

1. 隔离恢复 DSN 拒绝查询参数、片段、控制字符、非标准端口及无效端口。原规则只检查 URL 主体，asyncpg 可通过 host/user/database 查询参数覆盖主体，存在逃出隔离目标风险；现在在连接前拒绝，连接后仍复核角色和库名。
2. 对象键拒绝绝对路径、空段、点段、反斜杠和控制字符，确保隔离媒体路径只有一种规范形式。
3. 恢复计划明确归属、端口冲突、已有业务数据、交易关闭、备份及恢复引用；明确保留未知/其他项目服务。顺序为验证证据→只读与写入排空→存储及端口→隔离恢复→权限/金融/媒体对照→API/MCP/Hermes/审核→单采集→页面→未知订单核对。旧项目另用存储 API 和旧采集参考顺序，不启动已废止模型。计划无停止、删除或部署执行路径。
4. 清理检查要求独立备份校验、恢复证明、保留研究、零引用、1小时内引用扫描、未过期范围批准、精确候选清单哈希、最多1000条批次及恢复对照。整库/整桶范围拒绝；即使条件齐全，也仅返回可单独审查，不授权或执行删除。
5. Compose 新增顶级 config 文件来源目录门禁、未知资源引用拒绝、有限正数 CPU 校验、仅采集/执行器允许附加组10005；挂载签名时必须有该组。相对路径以给定项目根解释，不能依赖执行目录碰巧一致。API 内部 Hermes 授权令牌允许进入 API（审核配置鉴权），提供方密钥仍只可进入 Hermes。
6. 假配置固定项目内隧道、CA、签名、发现路径及网络入口值，保持交易关闭；运行环境未混入真实秘密。shell外部覆写仍由渲染后的目录门禁检查，未宣称低优先级dotenv能覆盖shell。
7. 新幂等准备创建私有项目运行目录，默认仅检查现有秘密和服务UID可读性。显式签名组动作把两个现有单链接文件设为root:10005、0440，不创建/替换/输出内容，不用0644公开秘密。主代理已给采集和执行器配置附加组，其他服务无此组。CA保留0644公开信任材料。
8. 只读存储探针限定连接、读取和整体预算，数据库强制只读会话及事务、检查TLS/隧道、当前角色权限；S3只head桶和带前缀MaxKeys=1读取，不扫根、不写删。连通成功与最小权限分开返回，过宽或未知权限会阻断存储接受门禁。
9. 全套525项中的恢复清理失败来自测试使用DROP DATABASE WITH(FORCE)终止其他角色进程，CREATEDB角色不具备pg_signal_backend。修复为先关闭本例连接，确认任务UUID库归当前角色所有，禁止新连接，再普通DROP并对退出中的后端有界等待；不增加角色权限，不终止其他角色，不吞掉最终清理失败。新增模拟残留退出与归属拒绝测试。
