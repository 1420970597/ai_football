# 报价写入超时后续核验

更新时间2026-11-06 05:30 UTC。状态研究中；E395单引用定位已部署，但E398一次及E401三次真实超时令该项生产验收恢复未完成。

目标：定位单引用定位后剩余5秒超时的实际等待类别，以同PID和相同时间窗口证据确定最小修复，保持报价身份、时间单调、完整盘口原子性及推荐价格不可变。责任目录为API报价写入、隔离行为测试及运维证据；依赖现有只读远端连接、当前部署SQL和自然报价更新。

当前证据：E401于05:23:08、05:23:48、05:25:03 UTC出现三次upsert_quotes执行超时，前两次同PID3414781，后一次3414687，prepare不超过0.057毫秒，执行约5秒。E402只读EXPLAIN没有ANALYZE或执行写语句，确认唯一引用索引探测后仅对需要更新的行主键定位；之前04:58至05:08的601个等待样本没有覆盖这些失败，不能据此判定无IO或无锁。高基数表及索引大小属于观察数据，不据此擅自清理历史或删除索引。

缺口：尚无三次超时当时同PID等待事件；EXPLAIN估计成本不能代替执行路径。设计决策：E405开启整1800秒、每秒一次、只限当前数据库用户与本项目application_name的有界等待采样，与E404审核观察重叠；仅输出类别、PID、时长、阻塞PID，不保存SQL原文和参数。暂不增加业务超时，不重试未知交易，不提高并发，不改变线上数据。

实现动作：先关联完整新窗失败与等待采样，再以最小SQL或批处理变更编写原子性、重复/乱序、并发、超时回滚测试；源码冻结后定向及完整回归，受控生效后重新实测。

验收场景：复现时同PID等待可解释；已存在/缺失引用、未知源时间、新旧事件、完整快照关闭、并发插入/更新保持原合同；失败后事务无部分写入；新全窗无报价超时仅作为窗口证据，不能推广为未来保证。若未捕获复现，则记录样本局限并继续针对性观察，不凭推测扩大改动。
