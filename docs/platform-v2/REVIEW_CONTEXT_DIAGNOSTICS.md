# 审核上下文差异与图片计量

更新时间：2026-11-07 15:53 UTC。状态：设计已记录，代码未写，真实联调未通过。

目标：为不必要重复读盘的后续根因分析保存足够且有限的差异证据，修正无回复原文时图片字节被统计为零的错误。责任目录services/api与tests；前置为已发布b8801c6审核及工具证据契约。当前E860真实推荐首次录入仅报告quote_or_score_context_changed，无法区分比分、阶段或市场身份字段；当前hermes_client汇总表达式将“自身媒体+回复媒体”的整体错误放在回复有效条件内，导致普通图片消息image_count非零而image_bytes为零。

设计决策：保留原字典相等判定和全部拒绝/接受顺序，只在该拒绝响应附加排序的context_changed_fields。允许输出的名称取自原固定quote_context契约；未知多余字段统一为unexpected_read_context，不输出任意键、旧值、新值或秘密。缺失字段与存在且为null必须区分；current_confirmation继续排除。使用已经读取的两个字典，不新增SQL、上游调用或缓存。图片计数只修正回复条件括号，自身图片始终计入，已删除/未就绪回复不计入，续轮依然为零，结构化视觉内容不改。

实现动作：先增加固定字段变化、缺失null、额外键与确认凭据的纯函数断言和真实临时数据库拒绝回执断言，以及自身图片、有效/删除回复、预备输入和续轮计量断言；在不可变旧业务源码上执行并保留原失败。随后最小修改，先定向测试，再干净提交冻结完整后端与固定框架；候选发布沿用既有空闲门和配置/财务摘要保护，不以这项诊断宣称3秒达标。

验收场景：原价格变化仍允许按系统当前价录入；任何原盘口或比分上下文变化仍拒绝，响应明确具体固定字段；缺失null不被合并为相等；任意额外键不泄露内容；可忽略确认字段仍可忽略；读写/SQL次数不增加；自身和有效回复字节合计正确，删除回复与续轮为零；原图及预处理复用不重复读取。失败处理：保留旧/新原退出与证据，修正后重跑同检查，不通过填旧比分、忽略差异或重放历史推荐掩盖问题。

剩余依赖：当前E837发布后完整30分钟官方对账及新自然图文；实际上下文变化根因需新证据，不等同于诊断已实现。真实模型多轮、精确盘口刷新及数据库延迟仍使170秒类样本远超3秒，不能在本阶段标为解决。
