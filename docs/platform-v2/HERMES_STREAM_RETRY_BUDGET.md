# Hermes 流式瞬态重试预算

更新时间：2026-11-06 09:28 UTC。工作包 E430，状态：代码、完整隔离验证及生产配置实载通过，部署后完整监控进行中。

目标：消除同一模型请求的隐藏流式重连，减少进入持久审核任务重试前的等待，缩短不可用上游占用的工作槽；不把失败提前记为无推荐，不降低连续分页或盘口绑定校验。责任目录为 Hermes 集成、部署配置和框架集成验收。前置依赖为固定 v0.22.5 镜像、既有30秒请求/stale预算及E424瞬态失败映射。

证据：08:55容器只读配置解析确认实际custom模型预算30秒、agent.api_max_retries=1和auto_recovery_cycles=0。固定框架的_StreamingCall._call另读HERMES_STREAM_RETRIES，缺省2，即单次外层调用可发起3次流式请求；_handle_stream_error对未交付瞬态失败重连并退避1/2秒。部署前生产未设置此变量，09:22仅Hermes重建后实载为0。该机制是额外等待来源，不宣称它解释所有分钟级等待；成功工具循环、空输出保护和5xx非流式兼容探针仍有各自预算。

设计决策：项目Compose及真实框架隔离启动器显式设置HERMES_STREAM_RETRIES=0，受保护配置白名单同步接纳并验证必须为0。只移除流式网络重连；保留stream_options兼容修正、工具完整性、30秒上游预算、E424与任务级持久退避。不会更换模型、调整prompt、扩大并发或增加外部请求。

实现动作与验收：补部署契约正常/缺失/非零拒绝测试；固定框架隔离场景核验上游503、静默、取消、真实MCP多轮及图片，并核对瞬态失败不产生假双回执、恢复可重试。冻结完整回归后使用自然空闲门仅重建Hermes，保持其它服务、资源、报价及既有台账。真实30分钟监控及原图/结论双端点击仍须另验；三秒端到端不因该配置自动达标。

失败处理：保留退出码、请求数和耗时，不禁用验收；若固定框架兼容性失败，纠正同一候选后原场景重跑。生产切换失败恢复原容器配置，保留任务与审计、不回滚业务数据库。
