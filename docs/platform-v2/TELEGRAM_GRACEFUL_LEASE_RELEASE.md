设计：新增 owner UUID 范围的内部 release 接口，单条 SQL 只将当前 owner 且仍活跃的 lease_until 设为当前时间；保留 owner、高水位、检查时间、错误、原文和台账。错误 owner、过期实例及重复调用均不能更改新 owner 的租约。无需手工强抢、删除检查点或缩短正常 TTL。租约结束不意味着消息已审核或结算。

采集器在首次 claim 发送前标记“可能持有”，覆盖请求已提交但响应丢失的情况。关闭顺序为取消并等待后台循环、媒体/认证任务及 Telegram 客户端和控制入口，最后一次有整体截止的 release 请求；没有尝试 claim 时跳过。成功验证响应后清除标记；失败或取消保留标记并传播真实错误，保留 TTL 故障恢复，不隐瞒成正常交接。release 不增加盲重试；API 幂等允许上层明确恢复。

实现动作：先写隔离失败用例；增加内部接口、受限 backend 方法与生命周期调用；在独立临时数据库运行 owner 隔离、游标保留、重复和并发用例；核验关闭时已经排空、传输超时不重试、无 claim 不请求以及取消传播；修复后重跑原失败，再冻结完整回归、构建和受控更新。不能把前一个旧版本的首次升级表现当作新版本释放能力证据。

验收场景：合法 owner 同时释放其多个群源；disabled 源可释放但不会被重新启用；另一个 owner 与已转交租约不受影响；重复释放返回 0；高水位不回退；缺认证 401、畸形 owner 422；并发旧 release 与新 claim 最终新 owner 仍有效。关闭任务与网络失败均有可观察结果，无提前释放、未排空写入或测试资金操作。

失败处理：原退出码、原日志与临时数据库名保存；测试失败不发布，不能以 force、跳过或加权限掩盖。线上释放失败维持原 90 秒超时恢复，标记 degraded/错误原因；只回滚本次容器，不回滚原文或业务数据。
