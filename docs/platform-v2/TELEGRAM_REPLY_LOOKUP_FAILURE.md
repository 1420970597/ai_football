目标：临时读取异常、会话失效或取消不能伪装成引用内容变化，制造额外原文版本、撤销已有审核并增加模型调用。责任目录为 services/collector 与 tests；前置是已有远端原文、检查点、最近消息恢复及媒体重试，不创建平行采集实现。

当前证据：E752 只读原退出0，原文“好家伙”没有编辑时间，13:06:14 第一版有完整引用，13:11:34 第二版仅把 reply_context 换成 unavailable，其他变化只有相应 version_key。存储未记录当次读取返回 None 还是抛异常，因此不能断言这一条必由网络异常触发。代码明确把 BaseException 与 None 合并，且同步调用异常也被吞掉；这会把断网、AuthKeyDuplicatedError 和子任务取消都误当内容观察。E749 只读原退出0，252条入库事件含大量首次归档旧发言，不能把它们当实时延迟；当前数据库12次最小往返中位245.402ms，p95按nearest-rank为490.247ms。

设计决策：成功返回 None 仍记录明确 unavailable，保留真实缺失引用的既有语义；读取抛异常则传播原异常，不提交降级版本、不推进检查点、不加入已处理缓存。现有实时入口把普通异常标记 deferred，最近消息与归档高水位继续补拉；会话失效沿既有路径撤销，取消继续传播。恢复成功后正常提交原文，不凭缓存假定引用未编辑或未删除。成功查到的原文/相册哈希与原图流程不变，不追溯重审或补投旧推荐。

实施动作：先用临时断网、同步启动异常、AuthKeyDuplicatedError 与取消证明旧路径失败；验证恢复后版本去重，以及成功 None 和并行作者读取不回退。只删除吞异常分支、区分 BaseException 与 None。E743 当前完整测试继续使用独立干净冻结树，后续源变更不进入 E743 候选；本工作包另行冻结和验收。

验收场景：已有完整版本遇临时错误不产生新版本；首次读取失败不确认成功且恢复后能提交；取消不被吞掉；真实 None 保留 unavailable；同步启动异常可观察；重复会话错误进入既有失效路径；作者任务排空后再传播错误。补跑 TG 接收、相册、近期恢复、租约交接与 worker 回归，再运行完整套件、镜像与真实消息观察。
