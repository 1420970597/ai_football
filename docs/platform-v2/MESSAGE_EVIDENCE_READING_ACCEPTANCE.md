# 专家原文与审核证据增量阅读验收

更新时间：2026-10-27；阶段：代码已写，真实临时 PostgreSQL 定向验证与浏览器隔离验证，未代表生产联调或正式发布。

## 目标与边界

解决消息详情、推荐详情和管理原文一次载入所有审核轨迹的问题。完整 Telegram 原文、回复、授权图片、模型输入输出、系统确认结果、全部比赛盘口绑定及工具返回继续可读。读取不会改写历史原文、审核记录、工具分片或推荐；不触发审核、上游请求、登录或投注。

本阶段只修改业务接口的原文阅读区域、共享去敏及阅读逻辑、网页消息弹窗和对应测试。主线负责全局私有缓存策略与最终全套、部署、Git 及发行；本阶段未操作生产或外部目录。

## 契约

| 入口 | 首次返回 | 继续读取 | 访问限制 |
| --- | --- | --- | --- |
| 用户消息详情 | 消息完整文字、授权媒体链接、30 条轨迹、30 条信号、独立最新系统确认 | 同一消息下的轨迹与推荐子资源 | 每次读取验证当前身份及完整历史权益；管理员可用管理员上下文 |
| 用户推荐详情 | 该推荐及消息、30 条轨迹、独立最新系统确认 | 通过同一消息的轨迹入口继续 | 同上；无媒体对象键或请求头透传 |
| 管理原文详情 | 同一有界消息结构及去敏来源证据 | 管理上下文的轨迹、推荐、工具入口 | 每次强制管理会话；不受普通用户 Cookie 优先级影响 |
| 消息轨迹分页 | 默认 30、最多 100；多审核任务按任务创建时间、任务标识、序号、轨迹标识升序 | 有签名的 `next_cursor`，直到为空 | 游标绑定消息、身份、会话摘要、用户或管理上下文、流类型与页大小；15 分钟有效 |
| 消息推荐分页 | 默认 30、最多 100；创建时间与标识键集 | 明确 `next_cursor`，不把 32 或 100 当成总条数 | 每页重新鉴权；过期权益不继续返回 |
| 完整工具返回 | 仅点击对应工具后加载；验证完整分片、字节数与 SHA-256 | 单次工具调用独立有界返回，继续沿轨迹读取其他调用 | 四种既有赛事工具白名单投影，不提供任意工具或数据库读取 |

初次轨迹 SQL 对工具分片去除 `data_base64` 后才返回，页面不自动重放全部分片。模型原始文字不按长度截断；内联图片编码、凭据、请求头、私有媒体对象位置会隐藏，授权图片走专用读取入口。工具重放沿用已有每调用 4 MiB 上限和字段白名单，缺失、损坏、串调用的快照返回 409，不返回“部分完整”。旧工具记录没有完整快照时明确提示仍可读原摘要，不伪造历史结果。

最新 `system_review_result` 独立查询，不依赖首 30 条是否包含它；网页只优先展示最新一份中文系统回执，保留其他模型和工具原始内容。旧测试及旧响应没有分页字段时继续完整显示其已有内容。

所有私有路由成功响应为 `private, no-store`，显式身份、权益、游标、缺失和快照校验错误同样携带私有不缓存。FastAPI 参数验证错误由主线全局 API 缓存策略覆盖。游标使用已有 HMAC 编码，不在内容中暴露会话令牌或会话摘要。
