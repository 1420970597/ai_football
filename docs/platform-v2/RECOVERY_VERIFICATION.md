# 隔离备份恢复与旧专家证据分类验证

更新时间：2026-10-26。阶段：隔离验证通过；真实旧数据迁移、生产备份及生产恢复未执行。所有样本为本项目内合成数据，不代表真实专家成绩或实际账户收益。

## 范围与操作限制

工具职责位于 `infra/recovery/`，行为测试位于 `tests/`。只接受显式隔离 PostgreSQL 角色 `recovery_test`、受限 Docker 主机名及 `recovery_*_test` 数据库；连接后再次核验实际角色与库名。命令入口不读取默认业务连接，不提供生产连接绕过开关。文件路径必须落在项目目录内，对象键禁止路径穿越。

本阶段没有读取外部归档、受保护配置或远端目录，没有迁移真实消息，也没有删除任何真实旧数据。现有官方旧结构及证据样本未在本次允许范围内提供，因此分类器仅为显式证据格式的暂存规划器，不能声称旧系统已迁移。

## 备份与恢复设计

1. 在只读、可重复读事务中固定结构、所有平台表、媒体引用和台账统计。外键决定恢复顺序；遇到外部依赖或循环依赖直接拒绝，不禁用约束。
2. 使用 PostgreSQL 二进制 COPY 保存精确十进制、UTC 时间、JSON、加密会话及哈希令牌。每块不超过 1 MiB，使用独立 32 字节备份密钥进行 AES-GCM 加密；清单同样加密，保存结构、行数、内容哈希和数据密钥版本引用。
3. 业务加密主密钥不放入备份，只保留引用。测试使用另一把原数据密钥验证恢复后的凭据可解密，错误数据密钥必须失败。备份密钥不能代替原业务密钥。
4. 引用图片按对象键稳定排序，校验 SHA-256 与单对象 8 MiB 上限。缺图、坏图或同键不同元数据导致备份失败，不能宣布成功。
5. 恢复前校验目标结构、清单、媒体及空目标；仅允许全新迁移产生的固定种子行。已有业务数据直接拒绝，已有不同内容对象绝不覆盖。
6. 目标事务内取得恢复互斥锁，再次检查空目标，统一清空种子行后按外键顺序 COPY。任何行数、台账、证据引用或媒体索引差异均回滚。媒体先写入隔离目标，数据库随后失败时可能留下孤儿对象；该状态不能算恢复完成，也不会自动清理其他对象。
7. CLI 设置连接、语句及整体 300 秒截止。备份先写权限为 0600 的同目录临时文件，成功后以不覆盖方式原子发布；失败只移除本次临时文件。该 CLI 文件发布流程尚未独立模拟磁盘断电，不能代替文件系统持久性演练。

这是受限的逻辑恢复演练工具，不包含 PostgreSQL 角色/权限、WAL、扩展、PITR、正式对象存储版本策略或跨地域灾备。二进制 COPY 要求结构兼容；生产升级和跨版本恢复还需独立验证。大规模真实数据的 RTO/RPO 不能从本次小样本外推。

## 2026-10-26 实测

以下命令在固定验证镜像中运行，CPU 上限 0.5 核、内存 512 MiB。`RECOVERY_TEST_ADMIN_URL` 仅包含任务 Docker 临时库角色，不能指向生产。

```sh
docker run --rm --cpus=0.5 --memory=512m \
  --network ai-football-v2-test-net \
  -e PYTHONDONTWRITEBYTECODE=1 \
  -e RECOVERY_TEST_ADMIN_URL \
  -v /root/ai_football:/w:ro -w /w \
  ai-football-verifier:v2.0.0-dev \
  python -m unittest discover -s tests -p test_recovery.py -v
```

实际运行使用显式的 `recovery_test` 角色和 `ai-football-v2-pgtest` 临时容器，每例建立两个 UUID 命名临时库、应用全部八次迁移，结束删除本例临时库。结果：**12 项通过，6.634 秒，退出码 0**；恢复覆盖 **37 张表及 1 个合成 PNG 对象**。单次备份 0.151629 秒，恢复 0.286590 秒，仅为小样本隔离测量。

并发测试在快照建立后、任何表 COPY 前通过另一连接提交新审计行；源随后为 2 条，备份和恢复均为快照时的 1 条，证明不会混入后续提交。该测试表明快照时间点的一致性，不承诺零数据丢失。

故障测试覆盖错误备份密钥、篡改密文块、缺少或错误媒体、非空目标、媒体冲突、结构不兼容、路径穿越、非隔离 DSN、重复推荐身份以及非专家旧模型记录。坏块恢复后目标仍无用户业务行，结构检查通过；媒体冲突保留原对象。每例独立库均在测试退出时清理。

## 旧记录分类命令

```sh
docker run --rm --cpus=0.5 --memory=256m \
  -e PYTHONDONTWRITEBYTECODE=1 \
  -v /root/ai_football:/w:ro -w /w \
  ai-football-verifier:v2.0.0-dev \
  python -m infra.recovery.cli classify \
    --input infra/recovery/samples/legacy-evidence.json
```

实际退出码 0；5 条公开合成输入输出：完整 1、可恢复 1、证据不足 2、排除非专家 1，可进入统计 1；`import_performed=false`、`deletion_performed=false`。CLI 仅输出数量，不打印原文、账户或密钥。

完整记录仍须精确比赛、玩法、期间、盘口线、方向以及推荐时系统报价。TG 原文倍率不作价格证据；报价与推荐时间差必须在 0—60 秒，且不能来自其他盘口。计入统计还须官方确认赛果、来源引用、可复算结算；滚球比分语义未知时保留待核对。重复身份双向隔离，数值相等的盘口线按同一身份处理，旧模型记录不进入专家统计。分类结果不自动写库。
