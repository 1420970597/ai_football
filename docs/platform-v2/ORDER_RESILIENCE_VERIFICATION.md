# 订单限额与未知回执恢复验证

更新日期：2026-10-26。本记录只使用隔离 Docker PostgreSQL、合成赛事和 Fake HTTP，不连接真实乐鱼账户、不发送资金请求。

## 覆盖范围

订单预留在本人账户行锁和策略行锁下执行。每日限额与开放敞口分别统计；`pending`、`submitting`、`accepted` 和 `unknown` 的预留本金不会被并发请求绕过。相同推荐的重复点击返回同一幂等订单，不创建第二份预留。

新增场景创建 6 条不同专家推荐，设置每单本金 2、每日限额 4、开放敞口 4，然后并发调用预留：最多 2 条进入 `pending`，其余 4 条收到限额拒绝；数据库预留总额为 4。随后调用紧急停止，所有待发送订单变为 `cancelled`，预留总额归零，停止操作不依赖会员续期或订单发送。

既有场景继续覆盖 HTTP 发送超时、执行器取消、租约过期、账户换绑、错误回执、准确回执和重复完成请求。发送结果未知时只保留 `unknown` 与原预留，下一次执行器领取不会盲目重发；只有带有匹配提供方订单号的回执才释放对应敞口，重复完成请求返回幂等结果。
