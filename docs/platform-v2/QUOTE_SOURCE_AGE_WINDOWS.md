## 两项可测代码问题

1. **父比赛版本可能阻断独立更新的报价。** 入库仅遍历比赛 upsert `RETURNING` 的 accepted 行。父比赛源时间旧而某盘口自身 ctsp 新时，盘口根本不进入其单调 upsert。冻结代码、无网络 Docker 控制流探针确认：父 upsert 返回空后 fresh quote 写入调用为 0。这是可构造缺陷；真实聚合仅证明部分父子时间不一致，尚未证明它解释了所有陈旧报价。最小修复应将已有且身份一致的比赛匹配与比赛字段版本更新分开，报价独立比较其源版本；完整快照关闭与比赛完场关闭仍须受可信父快照授权，不可因放开盘口入库而让旧完整快照删掉新项。用临时 PostgreSQL 验证旧父／新报价、错配身份、旧报价、旧完整删除、未知时间和事务失败。
2. **WS 延迟统计混用了事件与盘口时钟语义。** 现有 source lag/delivery age 取 `event.source_updated_at`，源自行 time/ctsp 等；实际报价源时由选项／盘口块 ctsp 提供。事件 P95 10.48 秒不能证明每条报价的延迟。应新增明确命名的 quote 级 source→receive/delivery 分位及未知／旧源计数，同时保留事件级指标；不改实际报价源时间。测试一行新 time、两盘口不同旧 ctsp、未知 ctsp、重复事件及有限统计窗口即可。
