研究日期：2026-10-13。研究对象是当前工作区 main 代码和 PostgreSQL 训练投影；没有开启真实投注，也没有把未晋级候选模型切入生产。文献清单由 OpenAlex Works API 串行抓取，保留查询词、DOI、作者、摘要片段和引用量，见 algorithm_papers.csv 与 model_papers.csv，两组各 80 篇；开源项目清单由 GitHub 检索 API 获取，算法/模型各 100 个，见 oss_algorithm_projects.csv、oss_model_projects.csv；两份 manifest 记录检索时间和请求结果。

文献证据分级如下：A 表示源码、原始论文页面或可复核的论文元数据/摘要；B 表示从论文方法抽取的可迁移原则；C 表示工程建议或本项目尚未测量的假设。OpenAlex 元数据不是逐篇全文审阅，因此报告只使用摘要和可核验方法结论，不把外部收益率迁移为本项目效果。

结论

当前系统没有结构性架构错误，但有三个已确证的 P0 实现缺陷：它们使“模型计算的赢”与“场馆结算的赢”不是同一个事件，并在权重、门控与训练标签中自我强化，已在 auto-betting-loss-audit 用 160 笔真实订单逐笔定量。其余方向与文献主流一致：赔率作为市场先验，Poisson/盘口支付分布提供结构化概率，按时间和比赛分组做前瞻验证，使用 Brier、Log loss 和校准信息，而不是只看命中率；候选模型还必须和同样本市场基准做配对比较。结论已整理为远程 issue #55（见文末）。

发现了一个确定的实现偏差和一个口径不一致，已经在本轮执行修复：

  1. PostgreSQL 训练采样原来对每场使用 ORDER BY i.at ... LIMIT 40，只保留最早的 40 条输入；SQLite 路径已经使用均匀时间采样。远程部署因此偏向开场阶段，和代码声明的多时点训练分布不一致。现在改为由已结算比赛驱动的 LATERAL 查询，在每场内部按决策时间均匀抽样，保留索引驱动和有界内存。
  2. core.learned_model.metrics() 原来没有执行与线上推理相同的完整盘口概率归一化，候选 artifact 的训练/验证 Brier 可能和线上输出口径不同。现在先调用完整盘口的 coherent normalization，再计算离线分数；二分类准确率仍保留为诊断指标，HAD Top-1 由 model_validation.evaluate() 单独报告。

这两项会影响模型训练分布和离线报告的可比性，但真正解释真实资金亏损的是更早一轮的逐笔对账（auto-betting-loss-audit）：滚球 AH 以累计比分为结算对象、负号复合盘口解析错误、“经济学风控”把单元素概率归一化为 100%。160 笔可匹配真实订单实际净亏 10.67 元（ROI -1.41%），而旧代码把同一批订单算成 +235.83 元；修复口径后 160/160 与场馆逐笔一致。缺陷经由算法权重、命中门控和训练标签自我强化，构成“设计方向正确、结果仍然亏损”的完整机制链。修复已落地、自动下注保持关闭；本报告新增的系统总评、亏损归因与开源对照用于回答“接下来怎么优化”。

研究方法与文献覆盖

两组文献的检索不是把标题按领域硬凑到篇数上限。脚本对每个查询取公开元数据，按标题和摘要关键词打分、去重并保留原始查询；模型组要求摘要包含 football/soccer/goal/match/sport 之一，算法组覆盖两类：直接体育投注/赔率方法，以及可迁移的概率预测、校准、评分规则、融合、在线学习和风险决策方法。算法组中约 19 篇是直接体育/投注研究，其余是通用于概率决策的统计方法；模型组约 79 篇含足球或足球进球模型。这个区分写入审计表，避免把天气预测论文伪装成足球收益证据。

系统设计合理性总评

维度结论依据
概率建模路线合理赔率先验 + Poisson 盘口反演是文献主流基线；全盘口归一化、proper scores、市场配对比较均已具备
验证设计基本合理时间隔离、按比赛聚类、前瞻预测时间校验正确；缺漂移监控、嵌套调参和 CLV
资金决策层不合理（部分修复）Kelly 只存在于展示层（≤25%），执行层固定 5 元且无全局未结算敞口；与文献及开源注码层共识不符
信息独立性不合理五个算法共享同一 OU/HAD 输入；方法分歧不是新增信息，同庄家公平赔率期望恒为 -m/(1+m)
结算与执行曾严重错误（已修复）AH 结算对象、负号解析、标量归一化三个 P0；订单终态对账仍缺
工程纪律合理版本化、影子部署、旧数据隔离、未知回执不重发、报价新鲜度检查
数据覆盖受限单庄单源、无事件/xG、无第二市场价格参照、无 CLV

总评：方向合理、执行曾有严重缺陷、信息源单薄。文献与开源对照同时支持三点：(1) 以赔率为先验、只信 proper scores 与同市场配对比较的框架正确；(2) 资金决策层必须与预测层闭合（分数 Kelly、回撤约束、全局敞口），当前尚未闭合；(3) 单一庄家赔率源是信息上限而非 bug——它使系统难以区分“模型错”与“价格错”。修复三个 P0 只恢复可评价性，不产生正期望：修正后同 160 笔的 ROI 聚类区间仍跨零。

已执行优化

1. PostgreSQL 训练采样修复

修改 store/training_data.py 的 _postgres_training_sample_query()：

  • 仍由已结算比赛集合驱动 CROSS JOIN LATERAL，避免 2300 万行输入的全局排序。
  • 每场在 at, algorithm, market, line, outcome 的稳定顺序上计算 ROW_NUMBER 与 COUNT。
  • 用 MOD((row_number - 1) * cap, total) < cap 选出均匀时间样本。
  • 状态中的采样口径从 earliest_qualified_inputs_per_match 改为 evenly_spaced_per_match。

这样保留同场多盘口和多算法，同时不把训练分布锁死在最早 40 条报价。

2. 离线指标与线上概率空间统一

修改 core/learned_model.py 的 metrics()：先对完整 HAD/OU/AH 组调用 coherent_probabilities()，再计算 Brier、Log loss 和二分类诊断。生产推荐方向仍使用同一组归一化概率，HAD Top-1 仍由 model_validation.evaluate() 单独报告。
