「实时倍率 → LLM + JEV 混合决策 → 自动买入」体育博彩交易机器人技术可行性与经济学可行性研究报告

研究对象：乐鱼体育（LEYU）、开云体育（KAIYUN）及同类实时赔率平台 构想架构：采集逐场实时倍率 → 在庄家调价瞬间触发决策 → LLM 大模型 + JEV 小模型组合判断 → 配合经济学算法计算仓位 → 自动下单

项目内容
报告版本v2.0
研究范围仅技术可行性与经济学可行性（不含法律合规评估）
分析口径架构分层可实现性 · 延迟预算 · 信息优势来源 · 期望值与成本 · 组合与仓位
核心结论分层看：L1–L4 技术可实现、工程可维护；L3 决策层的组合设计有明确最优解；但经济学上整个方案是结构性负期望，且 L5 的成交裁定权不在你手里。整体判定：不可行。

摘要

1. 架构本身没问题，问题在于它优化的是一个负期望系统。

LLM + JEV + 经济学算法的分层设计是正确的工程答案（§5、§6）：JEV 承担高频结构化判断（0.3–1.5s），LLM 承担低频非结构化推理（1.5–6s，不进关键路径），经济学算法栈承担去水、优势估计、分数 Kelly、约束（<1ms）。这套分工在技术上成立，且可以用 图 6 的路由矩阵严格推导出来。但——

2. 定价对手太强：打平需要在概率精度上相对优于庄家定价模型 11.4%。

在盘（滚球）足球水钱典型区间 8%–20%，均值 11.4%；赛前头部市场仅约 5.06%（68 家博彩公司样本）。由 EV = −m/(1+m) 得单注期望 −10.23%。打平条件是 p_model > p_fair × (1+m)，即需要 11.4% 的相对概率优势——而不是绝对优势。庄家的赔率不是猜测，是市场共识 + 风控因子；公开数据建模的现实相对优势在 0–2% 量级。

3. 关键路径已被对手方的接受延迟主导：29 秒 vs 你的模型 1.8 秒。

从场上事件到成交确认，乐观合计 29.0s（若 LLM 进关键路径则 35.0s）。其中属于你的部分只有约 1.8s（特征 + 经济学栈 0.5s + JEV 1.5s），其余由数据链路与庄家行为构成。庄家的下注接受延迟单项就是 5–10s，且可能改价或拒单。把 LLM 放在关键路径上，等于用 +6s 延迟换取零定价能力提升。

4. 固定成本会吃掉本来就微薄的优势。

月度基础设施与模型调用成本约 1,060**（35.3/天，其中"可摊销的模型成本"仅占 210）。蒙特卡洛显示：假设存在 +2% 优势且无平台风险，90 天盈利概率 61.4%；**扣除每日 35.3 成本后降至 45.4%。若叠加 25% 平台跑路/拒付概率，降至 29.2%。而无优势情形下只有 0.8%。

5. 蒙特卡洛结论（2 万次 / 90 天 / 5 注/天 / 每注 2% 银行）：

情形90 日余额中位数盈利概率
A · 无优势（滚球水钱 11.4%）$3,6310.8%
B · +2% 优势，无平台风险，不计成本$11,25961.4%
D · +2% 优势，扣除 $35/天 运行成本$7,65545.4%
C · +2% 优势，25% 概率跑路/拒付$9,26329.2%

读法：B 已经是乐观上界（假设优势真实存在），而 D 和 C 才是现实的约束条件——它们会同时生效，把 61.4% 压向 30% 以下。

架构的核心不对称（本报告的主线）：

这一点决定了后续所有经济学结论：优化决策侧的边际收益，会被执行侧的不确定性上限封顶。

3. L1 数据采集层：技术形态与工程约束

3.1 接口面：这是一个「私有前端」，不是「服务端点」

特征工程后果
无公开 API / 无文档无契约、无版本号、无变更日志、无沙箱
无 SLA / 无状态页无法区分"对手方故障"与"我方故障"
SPA + JS 动态渲染必须真实渲染执行，不能 HTTP 轮询
长连（WS/SSE）推送赔率需要维持长连接与心跳，连接断裂即失去行情
会话 / 设备指纹绑定状态机必须跨请求保持一致
端点域名持续轮换需持续探测可用端点、延迟分布、证书变更
估值与下注共用通道读路径与写路径耦合，风控同时作用于两者

这一形态的技术含义：DNS 安全研究已记录该类品牌数十个共用同一套基础设施（域名池 + CNAME 多层流量分发），域名池规模在 10⁵ 量级。对采集系统而言，这不是"数据接入"问题，而是"持续发现并维护一个不断漂移的端点集合"问题。

3.2 可对冲 vs 不可对冲

可对冲（工程手段有效）不可对冲（工程手段无效）
单点故障 → 多源冗余、多平台并行对手方单方面停盘（suspend）
端点半衰期 → 端点池 + 自动故障转移对手方随时变更协议与字段
对方无历史数据 → 本地时序库自建账户状态与被接受程度不可观测
推送断连 → 心跳 + 快速重连改价 / 拒单（见 §4.3）

数据源在盘更新间隔推送方式可编程下注技术评价

技术结论：若要捕捉"调价瞬间"，可选项只有两个—— (a) 直连私有前端：延迟最优（0.5–3s），但需承担全部端点漂移与协议变更成本； (b) 高端低延迟行情：延迟可接受，但仍然无法解决 §4.3 的成交裁定问题。

注意：数据源的精度上限本身就限制策略。The Odds API 的 40s 在盘间隔意味着基于它的"跳动检测"平均会滞后 20s——远大于整个决策链。

4. 微结构信号与延迟预算

4.1 微结构信号：本方案唯一可能的信息优势来源

"调价瞬间"这个构想的价值，在于它试图捕捉赔率的时间结构而非赔率的水平：

信号定义假设的预测含义
跳动频率单位时间内赔率变动次数高频跳动 = 信息正在流入
恢复时间跳价后回到新稳态的时长恢复慢 = 冲击较大，市场未充分定价
漂移速率赔率的定向变化速度持续单边漂移 = 聪明钱方向
跨平台离散度同市场不同平台价格差离散度扩大 = 定价分歧，套利窗口
停盘时长suspend 持续时间长停盘 = 重大事件，恢复后价格失真

这是唯一一类不在"瞬时价格"层面与庄家竞争的信息——你不是在比谁更快读到同一个数字，而是在比谁更快识别数字变化的方式。这个方向在理论上是成立的。

但必须诚实地指出边界：微结构信号在流动性充足、撮合连续的市场（如交易所）中信息含量高；在庄家单方面报价、可随时撤单的市场中，信号会频繁被"报价撤回"污染——你观察到的"跳动"很大一部分不是市场信号，而是对手方风控行为。

推论 1：把 JEV 从 1.5s 优化到 0.5s，只影响总延迟的 3%。 推论 2：LLM 进入关键路径会增加 +6s（+20%），而它不提供任何定价能力（§5.4）。 推论 3：真正的瓶颈是 ⑤ 之后到 ⑩ 之间的部分，而这两项都不在你的控制面内。

4.3 成交裁定：一个不能被工程解决的结构问题

机制技术描述对策略的影响
接受延迟在盘期下注请求被延迟 5–20s 后处理；交易所足球在盘最短约 5s决策时的价格与成交价格脱钩
停盘 suspend关键事件触发全市场挂起，报价被撤下你读到的"信号"可能是冻结值
改价 re-quote延迟窗口内改价，要求接受更差价关闭该选项则退化为拒单
拒单直接拒绝，理由不透明无反馈信号，无法用于学习
降限额 stake factoring触发条件为注单质量（CLV）而非盈亏优势被识别即被限幅，正期望无法复利
方向不对称社区实测报告：部分平台赔率变差时拒单、变好时照常成交期望值被系统性下调

工程语言描述：这是一个对手方持有单方面撤单权、且成交价可由对方在 5–10s 窗口内重定价的市场结构。用交易系统的话说：

等价于「交易所可以在你下单后 5–20 秒内决定是否撤销你的成交，并且可以在你获利时降低你的最大下单量」。 在这个结构下，"捕捉调价瞬间"的收益在进入成交前是不可实现的。

5. L3 决策层：LLM + JEV 混合架构

这是本方案的创新点，也是本报告最需要精确回答的部分。

5.1 两个模型的能力边界

维度LLM（大模型）JEV（决策模型）
输入非结构化文本/多模态非结构化 state（可含 JSON）
输出自然语言/结构化文本类型化判断：类别、是/否、评分 + 0–1 校准置信度
典型延迟1.5–6s（波动大）0.3–1.5s
单次成本高低
强项信息抽取、归因、解释、规则生成高频、结构化、需要校准判断的场景
弱项延迟与成本、数值回归数值预测（不是定价模型）

关键定性：JEV 是决策模型（"System One"），设计目标是对非结构化状态做带校准的离散判断。它不是赔率定价模型。公开信息未披露其可复现架构，因此只能研究其接口与定位，不能假定其内部机制。这一点对架构设计有决定性影响。

5.2 三路分流设计

分流原则（按延迟预算 × 调用频率 × 单次成本三维路由）：

路径承担任务延迟频率经济学贡献
A · 确定性规则/算法赔率跳动检测、跨平台套利判定、去水/公平概率、价值下注筛选、仓位计算<1ms极高直接
B · JEV微结构模式判断、价值下注的二值门控0.3–1.5s高中等（过滤，不创造）
C · LLM伤停/新闻抽取、异常归因与复盘、策略规则生成1.5–6s低间接（离线为主）

路由矩阵（data/routing_matrix.csv） 给出了逐任务的适配判定：

任务延迟预算调用频率单次成本适配模型经济学贡献
赔率跳动检测555规则/算法2
跨平台套利判定545规则/算法4
去水/公平概率555规则/算法2
价值下注筛选444JEV3
仓位计算545规则/算法4
微结构模式判断342JEV2
伤停/新闻抽取112LLM3
异常归因与复盘112LLM1
策略规则生成111LLM2

设计结论：

  1. LLM 只出现在矩阵的最后三行——全部是低频、非结构化、非关键路径的任务。
  2. JEV 出现在两行：价值下注门控、微结构模式判断——都是"给定特征、做带校准的二值/多分类判断"。
  3. 所有对延迟敏感的数值计算走路径 A：去水、Kelly、约束都是确定性算术，用模型去做是纯粹的性能浪费。

这是本报告对原构想最重要的一条修正：构想中"用 JEV 做决策"的位置是对的，但必须有路径 A 承载确定性计算。若把去水、Kelly 也交给模型，你会同时失去延迟和精度。

5.3 为什么 LLM 不能进关键路径

维度数值
LLM 延迟1.5–6.0s（方差极大）
关键路径占比增加 20%+（29.0s → 35.0s）
对定价能力的贡献≈ 0（LLM 不做数值定价）
单次成本高于 JEV 一个量级
调用频率上限每分钟数次（成本与延迟双重约束）

结论：LLM 的合理定位是离线/旁路——

  • 赛前：从伤停新闻、阵容公告中抽取结构化特征（此处时效窗口以小时计，LLM 延迟完全可接受）；
  • 事后：对拒单/异常成交做归因，生成新的规则候选（喂给路径 A）；
  • 在线旁路：对低时效的辅助信息做判断，结果异步注入特征库。

5.4 JEV 的适配度定位

环节JEV 适配度判断
赔率数值预测1 / 5数值回归问题，非离散判断
校准概率（去水）2 / 5确定性算术，不需要模型
微结构模式判断4 / 5特征 → 模式类别，正是设计场景
软信息（伤停/新闻）5 / 5非结构化 → 结构化判断
决策与仓位4 / 5可作门控，不能生成优势
下单执行1 / 5与模型能力无关

延迟占比：JEV + 经济学栈合计约 1.8s，占总延迟 <12%。

推论：模型侧优化的天花板是总延迟的 12%。剩下 88% 由数据链路（②③④⑤）与对手方行为（⑩）决定——后者不随你的代码质量变化。

6. L4 经济学算法栈

这一层是本方案中唯一有严格最优解的部分，也是投入产出比最高的部分。

6.1 六个阶段

阶段方法类型关键点
S1 去水 / 公平概率p_fair,i = (1/o_i) / Σ(1/o_j)；多源按历史校准度加权确定性庄家加价方式不总是比例式（存在 favorite-longshot bias），严格去水需按赔率区间分段校准
S2 优势估计edge = p_model × o − 1，叠加微结构信号统计优势估计的方差比点估计更重要
S3 不确定性折扣对 p_model 做后验方差收缩（shrinkage）贝叶斯抵消模型过度自信；这是防止负期望被放大的关键
S4 仓位（分数 Kelly）f* = (bp − q)/b × λ，λ ≈ 0.2–0.5最优化全 Kelly 在参数不确定时会导致过高破产概率
S5 组合约束同场/相关性敞口上限、单注上限、账户暴露上限约束滚球注单在时间上强相关（同一场比赛的多个市场是同一风险因子）
S6 成本摊销与执行过滤扣除调用成本与失败率；预测成交概率，放弃低概率单工程成交概率预测是这类系统最容易被忽略、又最影响实际收益的模块

6.2 数学形式

去水（fair probability）：

S=\sum_{i=1}^{n}\frac{1}{o_i}=1+m, p_i^{\text{fair}}=\frac{1/o_i}{S}

期望值：

\mathrm{EV}=p\cdot o-1=\frac{p}{p^{\text{implied}}}-1, p^{\text{implied}}=\frac{1}{o}

分数 Kelly：

f^{*}=\lambda\cdot\frac{b\,p-q}{b}, b=o-1,\ q=1-p,\ \lambda\in[0.2,0.5]

为什么必须分数 Kelly：全 Kelly 的最优性证明假设 p 已知且准确。当 p 存在估计误差时，f* 被系统性高估，长期增长率从最优转为次优甚至为负。学界对体育投注实务方法的综述（Walsh & Joshi, arXiv:2107.08827）指出：现代组合理论与 Kelly 的各种实务修正，本质都是在缓解正式模型不现实假设带来的额外风险。

执行过滤（S6）的形式化：设成交概率 q_fill，则有效期望为

\mathrm{EV}_{\text{eff}}=q_{\text{fill}}\cdot\mathrm{EV}-\text{cost}_{\text{exec}}

由于 §4.3 的机制，q_fill 不是常数，而是 EV 的递减函数——你越是有优势，越可能被拒单或降额。这一点无法通过算法栈解决，只能通过参数保守化（λ 下调）来缓解，代价是收益率进一步下降。

6.3 必须承认的上限

S1–S6 全部是「给定 p_model 之后」的最优处理。 它们能让一个真实存在的优势实现最大几何增长率， 但无法创造优势。 若 p_model 不含信息，整条栈只是在更精细地分配一个负期望。

这是判断本方案经济可行性的分水岭：模型工程的复杂度，与期望值的符号无关。

四条关键读法：

  1. 情形 A 是默认结局：无优势时 99.2% 路径亏损，且亏损是对数坐标下的近似直线——稳定的指数衰减。这就是水钱的数学形状。
  2. 情形 B 是乐观上界：即使假设 +2% 优势真实存在且不计任何成本，也只有 61.4% 路径盈利。原因：2% 的优势相对于 2% 的下注比例与赔率波动，信噪比低，90 天样本量不足以稳定实现期望。这说明"回测盈利 → 实盘盈利"之间存在巨大方差鸿沟。
  3. 情形 D 揭示成本的破坏力：每日 35.3 固定成本，把盈利概率从 61.4% 拉到 45.4%——**约 16 个百分点的损失**。而这个成本相对 10,000 本金（0.35%/天）与 +2% 优势是同一个量级。
  4. 情形 C 是叠加后的现实：平台风险把 61.4% 压到 29.2%。而 D 和 C 会同时生效——真实盈利概率应低于任一单项。

9.3 敏感性说明

关于 25% 这个参数：本报告不给它任何精确性假设，它只用于说明量级。读者可在 scripts/make_figures.py 的 fig11_montecarlo() 中改为 5%、50% 或与之无关的累积风险模型重跑。结论方向不变：只要该风险不是零，它就会显著压低盈利概率。

更贴近现实的建模方式是把"账户风险"视为与盈利水平正相关的累积过程——因为触发限额与拒付的因素是注单质量（CLV），而非账户余额。也就是说：你的成功本身就是风险的触发条件。本报告的固定概率模型实际上是乐观简化。

9.4 微结构信号能改变结论吗？

这是本方案唯一可能改变结论的方向，值得单独量化。假设微结构信号能提供额外的相对优势 ε：

总相对优势 m_needed=11.4% 下需要的 ε现实评估
打平11.4%极不可能（公开数据 0–2%）
净收益 +2%（扣成本后）~13%更不可能
净收益 +2%（假设交易所 3% 水钱场景）~5%仍远超公开数据可得水平

结论：微结构信号在理论上是正确的竞争维度，但要把打平所需的 11.4% 相对优势大部分由它提供，没有公开证据支持。工程上应该把它当作边际改善（提高 q_fill、降低无效调用、改善 S6 执行过滤），而不是当作优势来源。

10.1 结论

问题回答
Q1 能不能实现？技术上可以，但分层差异巨大。 L1–L4 可实现、可维护；L5 存在结构性的不可控（接受延迟、改价、拒单、限额）。
Q2 经济学上是否正期望？否。 在盘水钱均值 11.4% → EV = −10.23%；打平需相对优于庄家定价模型 11.4%，公开数据可得优势 0–2%。
架构设计正确吗？分层设计正确，且能得到严格最优解。 LLM + JEV + 经济学算法的三路分流是本类问题的最优工程答案（§5.2）。但它优化的是一个负期望系统。
最有价值的部分是什么？L4 经济学算法栈（可维护性 4 分）与 L2 特征/微结构（可实现性 5 分）。这两层的方法论可以完整迁移到其它正期望场景。

10.2 直接回答原构想

不可行——但原因与多数直觉相反。

它不是"技术做不到"，也不是"模型不够强"。

  • 架构是对的：LLM 承担非结构化低频推理、JEV 承担高频结构化判断、经济学算法承担确定性最优计算——这个分流是正确的，而且是可推导的（§5.2）。
  • 瓶颈不在模型侧：你的决策链只占总延迟的 6%（1.8s/29.0s），模型优化的天花板是 12%。
  • 失败点在两处结构性约束：
  • 定价：打平需 11.4% 相对优势，而可得优势 0–2%（差一个数量级）；
  • 成交：5–20s 的接受延迟 + 改价 + 拒单 + 基于 CLV 的降限额，使"捕捉调价瞬间"的收益在成交前不可实现。

叠加固定成本（$35.3/天）后，即使假设优势真实存在，90 天盈利概率也从 61.4% 降至 45.4%，再叠加平台风险降至 29.2%；而假设优势不存在（更接近现实），盈利概率是 0.8%。
