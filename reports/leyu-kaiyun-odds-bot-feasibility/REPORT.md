# 「实时倍率 → LLM + JEV 混合决策 → 自动买入」体育博彩交易机器人技术可行性与经济学可行性研究报告

**研究对象**：乐鱼体育（LEYU）、开云体育（KAIYUN）及同类实时赔率平台
**构想架构**：采集逐场实时倍率 → 在庄家调价瞬间触发决策 → LLM 大模型 + JEV 小模型组合判断 → 配合经济学算法计算仓位 → 自动下单

| 项目 | 内容 |
| --- | --- |
| 报告版本 | v2.0 |
| 研究范围 | **仅技术可行性与经济学可行性**（不含法律合规评估） |
| 分析口径 | 架构分层可实现性 · 延迟预算 · 信息优势来源 · 期望值与成本 · 组合与仓位 |
| 核心结论 | **分层看：L1–L4 技术可实现、工程可维护；L3 决策层的组合设计有明确最优解；但经济学上整个方案是结构性负期望，且 L5 的成交裁定权不在你手里。整体判定：不可行。** |

## 摘要

**1. 架构本身没问题，问题在于它优化的是一个负期望系统。**

LLM + JEV + 经济学算法的分层设计是**正确的工程答案**（§5、§6）：JEV 承担高频结构化判断（0.3–1.5s），LLM 承担低频非结构化推理（1.5–6s，**不进关键路径**），经济学算法栈承担去水、优势估计、分数 Kelly、约束（<1ms）。这套分工在技术上成立，且可以用 `图 6` 的路由矩阵严格推导出来。但——

**2. 定价对手太强：打平需要在概率精度上相对优于庄家定价模型 11.4%。**

在盘（滚球）足球水钱典型区间 8%–20%，**均值 11.4%**；赛前头部市场仅约 5.06%（68 家博彩公司样本）。由 `EV = −m/(1+m)` 得单注期望 **−10.23%**。打平条件是 `p_model > p_fair × (1+m)`，即需要 **11.4% 的相对概率优势**——而不是绝对优势。庄家的赔率不是猜测，是市场共识 + 风控因子；公开数据建模的现实相对优势在 **0–2%** 量级。

**3. 关键路径已被对手方的接受延迟主导：29 秒 vs 你的模型 1.8 秒。**

从场上事件到成交确认，乐观合计 **29.0s**（若 LLM 进关键路径则 **35.0s**）。其中**属于你的部分只有约 1.8s**（特征 + 经济学栈 0.5s + JEV 1.5s），其余由数据链路与庄家行为构成。**庄家的下注接受延迟单项就是 5–10s**，且可能改价或拒单。把 LLM 放在关键路径上，等于用 +6s 延迟换取零定价能力提升。

**4. 固定成本会吃掉本来就微薄的优势。**

月度基础设施与模型调用成本约 **$1,060**（$35.3/天，其中"可摊销的模型成本"仅占 $210）。蒙特卡洛显示：假设存在 +2% 优势且无平台风险，90 天盈利概率 61.4%；**扣除每日 $35.3 成本后降至 45.4%**。若叠加 25% 平台跑路/拒付概率，降至 **29.2%**。而无优势情形下只有 **0.8%**。

**5. 蒙特卡洛结论（2 万次 / 90 天 / 5 注/天 / 每注 2% 银行）：**

| 情形 | 90 日余额中位数 | 盈利概率 |
| --- | --- | --- |
| A · 无优势（滚球水钱 11.4%） | $3,631 | **0.8%** |
| B · +2% 优势，无平台风险，不计成本 | $11,259 | 61.4% |
| D · +2% 优势，扣除 $35/天 运行成本 | $7,655 | **45.4%** |
| C · +2% 优势，25% 概率跑路/拒付 | $9,263 | **29.2%** |

> 读法：B 已经是**乐观上界**（假设优势真实存在），而 D 和 C 才是现实的约束条件——**它们会同时生效**，把 61.4% 压向 30% 以下。

## 2. 系统分层架构总览

![图 5 LLM + JEV 混合决策架构](images/fig5_hybrid_architecture.png)

| 层 | 职责 | 关键指标 | 归属 |
| --- | --- | --- | --- |
| **L1 采集** | 长连推送、多源冗余、端点池、归一化 | 可用率、端到端延迟 | 你 |
| **L1′ 微结构提取** | 跳动频率、恢复时间、漂移速率、价差、深度代理 | 单次 <1ms | 你 |
| **L2 特征** | 去水隐含概率、无风险参考线、跨市场一致性 | 单次 <1ms | 你 |
| **L3 决策** | **三路分流**：确定性规则 / JEV / LLM | 见 §5 | 你 |
| **L4 经济学算法栈** | 优势估计、分数 Kelly、相关性约束、成本摊销、可行性过滤 | 单次 <1ms | 你 |
| **L5 执行** | 下注队列、幂等去重、速率整形、拒单状态机、对账 | 5–20s（含对手方延迟） | **部分在对手方** |
| **L6 反馈校准** | 结算回归、CLV 归因、Brier/ECE 评估、参数调优 | 离线 | 你 |

**架构的核心不对称（本报告的主线）：**

> L1–L4 全部属于你，可以被优化到亚秒级；**L5 之后由对手方的风控系统裁定**。
> 这意味着：你可以把"决策"做到极致，但"成交与否"不在你的控制面内。

这一点决定了后续所有经济学结论：**优化决策侧的边际收益，会被执行侧的不确定性上限封顶。**

## 3. L1 数据采集层：技术形态与工程约束

![图 1 目标平台的技术形态与接口面](images/fig1_platform_infra.png)

### 3.1 接口面：这是一个「私有前端」，不是「服务端点」

| 特征 | 工程后果 |
| --- | --- |
| **无公开 API / 无文档** | 无契约、无版本号、无变更日志、无沙箱 |
| **无 SLA / 无状态页** | 无法区分"对手方故障"与"我方故障" |
| **SPA + JS 动态渲染** | 必须真实渲染执行，不能 HTTP 轮询 |
| **长连（WS/SSE）推送赔率** | 需要维持长连接与心跳，连接断裂即失去行情 |
| **会话 / 设备指纹绑定** | 状态机必须跨请求保持一致 |
| **端点域名持续轮换** | 需持续探测可用端点、延迟分布、证书变更 |
| **估值与下注共用通道** | 读路径与写路径耦合，风控同时作用于两者 |

**这一形态的技术含义**：DNS 安全研究已记录该类品牌**数十个共用同一套基础设施**（域名池 + CNAME 多层流量分发），域名池规模在 10⁵ 量级。对采集系统而言，这不是"数据接入"问题，而是**"持续发现并维护一个不断漂移的端点集合"**问题。

### 3.2 可对冲 vs 不可对冲

| 可对冲（工程手段有效） | 不可对冲（工程手段无效） |
| --- | --- |
| 单点故障 → 多源冗余、多平台并行 | 对手方单方面停盘（suspend） |
| 端点半衰期 → 端点池 + 自动故障转移 | 对手方随时变更协议与字段 |
| 对方无历史数据 → 本地时序库自建 | 账户状态与被接受程度不可观测 |
| 推送断连 → 心跳 + 快速重连 | 改价 / 拒单（见 §4.3） |

### 3.3 数据源可得性矩阵（技术维度）

| 数据源 | 在盘更新间隔 | 推送方式 | 可编程下注 | 技术评价 |
| --- | --- | --- | --- | --- |
| The Odds API | **40 秒**（精选市场） | REST 轮询 | ❌ | 延迟量级与"调价瞬间"不匹配 |
| TheRundown | 亚秒级 | WebSocket（Ultra+） | ❌ | 只能看盘 |
| Pinnacle API | — | REST | ✅ | **2025-07-23 起对公众关闭**，需商业申请 |
| 第三方转售（Pinnacle 行情） | 低 | 推送 | ❌ | $99–$229/月 |
| **Betfair Exchange API** | 推送（Streaming API） | Streaming + REST | ✅ | 唯一公开可编程下注通道；价格由撮合决定 |
| 直接采集目标平台前端 | 0.5–3s | WS/SSE | 需自行逆向 | **延迟最优，工程成本与不确定性最高** |

**技术结论**：若要捕捉"调价瞬间"，可选项只有两个——
(a) 直连私有前端：延迟最优（0.5–3s），但需承担全部端点漂移与协议变更成本；
(b) 高端低延迟行情：延迟可接受，但**仍然无法解决 §4.3 的成交裁定问题**。

注意：数据源的**精度上限**本身就限制策略。The Odds API 的 40s 在盘间隔意味着基于它的"跳动检测"平均会滞后 20s——**远大于整个决策链**。

## 4. 微结构信号与延迟预算

### 4.1 微结构信号：本方案唯一可能的信息优势来源

"调价瞬间"这个构想的价值，在于它试图捕捉**赔率的时间结构**而非**赔率的水平**：

| 信号 | 定义 | 假设的预测含义 |
| --- | --- | --- |
| 跳动频率 | 单位时间内赔率变动次数 | 高频跳动 = 信息正在流入 |
| 恢复时间 | 跳价后回到新稳态的时长 | 恢复慢 = 冲击较大，市场未充分定价 |
| 漂移速率 | 赔率的定向变化速度 | 持续单边漂移 = 聪明钱方向 |
| 跨平台离散度 | 同市场不同平台价格差 | 离散度扩大 = 定价分歧，套利窗口 |
| 停盘时长 | suspend 持续时间 | 长停盘 = 重大事件，恢复后价格失真 |

**这是唯一一类不在"瞬时价格"层面与庄家竞争的信息**——你不是在比谁更快读到同一个数字，而是在比谁更快识别**数字变化的方式**。这个方向在理论上是成立的。

**但必须诚实地指出边界**：微结构信号在**流动性充足、撮合连续**的市场（如交易所）中信息含量高；在**庄家单方面报价、可随时撤单**的市场中，信号会频繁被"报价撤回"污染——你观察到的"跳动"很大一部分不是市场信号，而是对手方风控行为。

### 4.2 延迟预算

![图 4 延迟预算](images/fig4_latency_budget.png)

| 阶段 | 乐观 | 保守 | 归属 |
| --- | --- | --- | --- |
| ① 场上事件发生 | 0 | 0 | — |
| ② 场馆数据采集（数据中心现场采集员） | 2.0 | 5.0 | 数据商 |
| ③ 数据商 → 庄家交易系统推送 | 1.0 | 3.0 | 数据商/庄家 |
| ④ 庄家模型重算 + 风控复核 | 1.0 | 4.0 | 庄家 |
| ⑤ 新赔率抵达你的采集端 | 0.5 | 3.0 | 你（部分） |
| ⑥ **特征计算 + 经济学算法栈** | 0.05 | 0.5 | **你** |
| ⑦ **JEV 决策调用** | 0.3 | 1.5 | **你** |
| ⑧ LLM 决策调用（**仅慢通路**） | 1.5 | 6.0 | 你（不应进关键路径） |
| ⑨ 下单请求 → 庄家风控 | 0.5 | 2.0 | 你→庄家 |
| ⑩ **庄家下注接受延迟** | 5.0 | 10.0 | **庄家** |
| ⑪ 成交结果：旧价 / 改价 / 拒单 | — | — | **庄家** |
| **关键路径合计（不含 LLM）** | — | **29.0s** | |
| **全路径合计（含 LLM）** | — | **35.0s** | |

**分解结论（关键）**：

```
属于你的决策预算        约 1.8s   （⑥ 0.5 + ⑦ 1.5）
属于对手方的裁定窗口    5–10s     （⑩，单项即超过你的全部决策时间）
不可控的数据链路        4.5–15s   （②③④⑤）
```

> **推论 1**：把 JEV 从 1.5s 优化到 0.5s，只影响总延迟的 3%。
> **推论 2**：LLM 进入关键路径会增加 **+6s（+20%）**，而它不提供任何定价能力（§5.4）。
> **推论 3**：真正的瓶颈是 ⑤ 之后到 ⑩ 之间的部分，而**这两项都不在你的控制面内**。

### 4.3 成交裁定：一个不能被工程解决的结构问题

![图 9 赔率跳动瞬间的真实时序](images/fig9_odds_tick_sequence.png)

| 机制 | 技术描述 | 对策略的影响 |
| --- | --- | --- |
| **接受延迟** | 在盘期下注请求被延迟 5–20s 后处理；交易所足球在盘最短约 5s | 决策时的价格与成交价格脱钩 |
| **停盘 suspend** | 关键事件触发全市场挂起，报价被撤下 | 你读到的"信号"可能是冻结值 |
| **改价 re-quote** | 延迟窗口内改价，要求接受更差价 | 关闭该选项则退化为拒单 |
| **拒单** | 直接拒绝，理由不透明 | 无反馈信号，无法用于学习 |
| **降限额 stake factoring** | 触发条件为**注单质量（CLV）而非盈亏** | 优势被识别即被限幅，正期望无法复利 |
| **方向不对称** | 社区实测报告：部分平台赔率变差时拒单、变好时照常成交 | 期望值被系统性下调 |

**工程语言描述**：这是一个**对手方持有单方面撤单权、且成交价可由对方在 5–10s 窗口内重定价**的市场结构。用交易系统的话说：

> **等价于「交易所可以在你下单后 5–20 秒内决定是否撤销你的成交，并且可以在你获利时降低你的最大下单量」。**
> 在这个结构下，"捕捉调价瞬间"的收益**在进入成交前是不可实现的**。

## 5. L3 决策层：LLM + JEV 混合架构

这是本方案的创新点，也是本报告最需要精确回答的部分。

### 5.1 两个模型的能力边界

| 维度 | LLM（大模型） | JEV（决策模型） |
| --- | --- | --- |
| 输入 | 非结构化文本/多模态 | 非结构化 state（可含 JSON） |
| 输出 | 自然语言/结构化文本 | **类型化判断**：类别、是/否、评分 + **0–1 校准置信度** |
| 典型延迟 | 1.5–6s（波动大） | 0.3–1.5s |
| 单次成本 | 高 | 低 |
| 强项 | 信息抽取、归因、解释、规则生成 | **高频、结构化、需要校准判断**的场景 |
| 弱项 | 延迟与成本、数值回归 | 数值预测（**不是定价模型**） |

**关键定性**：JEV 是**决策模型**（"System One"），设计目标是对非结构化状态做**带校准的离散判断**。它**不是**赔率定价模型。公开信息未披露其可复现架构，因此只能研究其**接口与定位**，不能假定其内部机制。这一点对架构设计有决定性影响。

### 5.2 三路分流设计

![图 6 决策路由矩阵](images/fig6_routing_matrix.png)

**分流原则（按延迟预算 × 调用频率 × 单次成本三维路由）：**

| 路径 | 承担任务 | 延迟 | 频率 | 经济学贡献 |
| --- | --- | --- | --- | --- |
| **A · 确定性规则/算法** | 赔率跳动检测、跨平台套利判定、去水/公平概率、价值下注筛选、仓位计算 | <1ms | 极高 | 直接 |
| **B · JEV** | 微结构模式判断、价值下注的二值门控 | 0.3–1.5s | 高 | 中等（**过滤，不创造**） |
| **C · LLM** | 伤停/新闻抽取、异常归因与复盘、策略规则生成 | 1.5–6s | 低 | 间接（离线为主） |

**路由矩阵（`data/routing_matrix.csv`）** 给出了逐任务的适配判定：

| 任务 | 延迟预算 | 调用频率 | 单次成本 | **适配模型** | 经济学贡献 |
| --- | :---: | :---: | :---: | --- | :---: |
| 赔率跳动检测 | 5 | 5 | 5 | **规则/算法** | 2 |
| 跨平台套利判定 | 5 | 4 | 5 | **规则/算法** | 4 |
| 去水/公平概率 | 5 | 5 | 5 | **规则/算法** | 2 |
| 价值下注筛选 | 4 | 4 | 4 | **JEV** | 3 |
| 仓位计算 | 5 | 4 | 5 | **规则/算法** | 4 |
| 微结构模式判断 | 3 | 4 | 2 | **JEV** | 2 |
| 伤停/新闻抽取 | 1 | 1 | 2 | **LLM** | 3 |
| 异常归因与复盘 | 1 | 1 | 2 | **LLM** | 1 |
| 策略规则生成 | 1 | 1 | 1 | **LLM** | 2 |

**设计结论**：
1. **LLM 只出现在矩阵的最后三行**——全部是低频、非结构化、**非关键路径**的任务。
2. **JEV 出现在两行**：价值下注门控、微结构模式判断——都是"给定特征、做带校准的二值/多分类判断"。
3. **所有对延迟敏感的数值计算走路径 A**：去水、Kelly、约束都是确定性算术，**用模型去做是纯粹的性能浪费**。

> **这是本报告对原构想最重要的一条修正**：构想中"用 JEV 做决策"的位置是对的，但**必须有路径 A 承载确定性计算**。若把去水、Kelly 也交给模型，你会同时失去延迟和精度。

### 5.3 为什么 LLM 不能进关键路径

| 维度 | 数值 |
| --- | --- |
| LLM 延迟 | 1.5–6.0s（方差极大） |
| 关键路径占比 | 增加 20%+（29.0s → 35.0s） |
| 对定价能力的贡献 | **≈ 0**（LLM 不做数值定价） |
| 单次成本 | 高于 JEV 一个量级 |
| 调用频率上限 | 每分钟数次（成本与延迟双重约束） |

**结论**：LLM 的合理定位是**离线/旁路**——
- **赛前**：从伤停新闻、阵容公告中抽取结构化特征（此处时效窗口以小时计，LLM 延迟完全可接受）；
- **事后**：对拒单/异常成交做归因，生成新的规则候选（喂给路径 A）；
- **在线旁路**：对低时效的辅助信息做判断，结果**异步**注入特征库。

### 5.4 JEV 的适配度定位

![图 10 JEV 的定位与延迟占比](images/fig10_jev_position.png)

| 环节 | JEV 适配度 | 判断 |
| --- | :---: | --- |
| 赔率数值预测 | 1 / 5 | 数值回归问题，非离散判断 |
| 校准概率（去水） | 2 / 5 | 确定性算术，不需要模型 |
| **微结构模式判断** | 4 / 5 | 特征 → 模式类别，正是设计场景 |
| **软信息（伤停/新闻）** | 5 / 5 | 非结构化 → 结构化判断 |
| 决策与仓位 | 4 / 5 | 可作门控，**不能生成优势** |
| 下单执行 | 1 / 5 | 与模型能力无关 |

**延迟占比**：JEV + 经济学栈合计约 1.8s，占总延迟 **<12%**。

> **推论**：模型侧优化的天花板是总延迟的 12%。剩下 88% 由数据链路（②③④⑤）与对手方行为（⑩）决定——**后者不随你的代码质量变化**。

## 6. L4 经济学算法栈

![图 8 经济学算法栈](images/fig8_econ_algo_stack.png)

这一层是本方案中**唯一有严格最优解**的部分，也是投入产出比最高的部分。

### 6.1 六个阶段

| 阶段 | 方法 | 类型 | 关键点 |
| --- | --- | --- | --- |
| **S1 去水 / 公平概率** | `p_fair,i = (1/o_i) / Σ(1/o_j)`；多源按历史校准度加权 | 确定性 | 庄家加价方式不总是比例式（存在 favorite-longshot bias），严格去水需按赔率区间分段校准 |
| **S2 优势估计** | `edge = p_model × o − 1`，叠加微结构信号 | 统计 | 优势估计的**方差**比点估计更重要 |
| **S3 不确定性折扣** | 对 `p_model` 做后验方差收缩（shrinkage） | 贝叶斯 | 抵消模型过度自信；这是防止负期望被放大的关键 |
| **S4 仓位（分数 Kelly）** | `f* = (bp − q)/b × λ`，λ ≈ 0.2–0.5 | 最优化 | 全 Kelly 在参数不确定时会导致过高破产概率 |
| **S5 组合约束** | 同场/相关性敞口上限、单注上限、账户暴露上限 | 约束 | 滚球注单在时间上强相关（同一场比赛的多个市场是同一风险因子） |
| **S6 成本摊销与执行过滤** | 扣除调用成本与失败率；预测成交概率，放弃低概率单 | 工程 | **成交概率预测**是这类系统最容易被忽略、又最影响实际收益的模块 |

### 6.2 数学形式

**去水（fair probability）**：

$$S=\sum_{i=1}^{n}\frac{1}{o_i}=1+m,\qquad p_i^{\text{fair}}=\frac{1/o_i}{S}$$

**期望值**：

$$\mathrm{EV}=p\cdot o-1=\frac{p}{p^{\text{implied}}}-1,\qquad p^{\text{implied}}=\frac{1}{o}$$

**分数 Kelly**：

$$f^{*}=\lambda\cdot\frac{b\,p-q}{b},\qquad b=o-1,\ q=1-p,\ \lambda\in[0.2,0.5]$$

**为什么必须分数 Kelly**：全 Kelly 的最优性证明假设 `p` **已知且准确**。当 `p` 存在估计误差时，`f*` 被系统性高估，长期增长率从最优转为次优甚至为负。学界对体育投注实务方法的综述（Walsh & Joshi, arXiv:2107.08827）指出：现代组合理论与 Kelly 的各种实务修正，**本质都是在缓解正式模型不现实假设带来的额外风险**。

**执行过滤**（S6）的形式化：设成交概率 `q_fill`，则有效期望为

$$\mathrm{EV}_{\text{eff}}=q_{\text{fill}}\cdot\mathrm{EV}-\text{cost}_{\text{exec}}$$

由于 §4.3 的机制，`q_fill` **不是常数**，而是 `EV` 的**递减函数**——你越是有优势，越可能被拒单或降额。这一点无法通过算法栈解决，只能通过参数保守化（λ 下调）来缓解，代价是收益率进一步下降。

### 6.3 必须承认的上限

> **S1–S6 全部是「给定 `p_model` 之后」的最优处理。**
> 它们能让一个**真实存在**的优势实现最大几何增长率，
> 但**无法创造优势**。
> 若 `p_model` 不含信息，整条栈只是在更精细地分配一个负期望。

这是判断本方案经济可行性的分水岭：**模型工程的复杂度，与期望值的符号无关。**

## 7. 经济学分析（一）：水钱与所需精度优势

### 7.1 水钱：报价里的税

![图 2 水钱与单注期望值](images/fig2_margin_and_ev.png)

| 市场 | 典型水钱 | 单注 EV |
| --- | --- | --- |
| 交易所（撮合模式，抽佣） | ~2.0% | −1.96% |
| 欧冠 / 网球 赛前 | 3–4.5% | −4.31%（按 4.5%） |
| 英超 赛前 1X2 | 4–6% | −4.76% |
| **滚球足球在盘（均值）** | **11.4%** | **−10.23%** |
| 滚球 同场串关/道具 | ~13% | −11.50% |
| 四串一（5.2%/腿 复利） | ~22.8% | −18.57% |
| 首个进球者 | 20–35% | −21.26% |
| 正确比分 | 25–45% | −24.24% |

**关键观察**：本构想的目标市场（滚球在盘）**恰好是水钱最贵的市场**。在盘市场的抽水是赛前头部的 2 倍以上。行业统计（Bitok Arena Research：12,000 注 / 6 家主流博彩 / 12 个月）给出赛果市场 6.8% vs **在盘市场 11.4%**；Bet Better Margin Index（68 家、每日更新）给出头部市场均值 5.06%。

> **结构性推论**：在盘市场的高水钱**不是效率损失，而是产品定价**——庄家为"即时性 + 高频 + 低延迟"收取的溢价。选择该市场，等于主动选择最高的结构性劣势。

### 7.2 打平所需的精度优势

![图 3 需要的概率精度优势](images/fig3_required_edge.png)

打平条件 `p_model × o > 1`，代入隐含概率得：

$$p_{\text{model}} > p^{\text{fair}}\times(1+m)$$

即**需要的相对概率优势恰为水钱 m**：

| 水钱档位 | p=50% 标的需超出 | p=30% 标的需超出 | p=10% 标的需超出 |
| --- | --- | --- | --- |
| 3%（交易所） | 1.5 pp | 0.9 pp | 0.3 pp |
| 5%（赛前头部） | 2.5 pp | 1.5 pp | 0.5 pp |
| 8.07%（平均） | 4.0 pp | 2.4 pp | 0.8 pp |
| **11.4%（滚球均值）** | **5.7 pp** | **3.4 pp** | **1.1 pp** |
| 15%（滚球高阶） | 7.5 pp | 4.5 pp | 1.5 pp |
| 20%（滚球上限） | 10.0 pp | 6.0 pp | 2.0 pp |

**分母不对等问题**：你需要打败的是**庄家自己的定价模型**，而不是"随机猜测"。庄家的赔率构成是：

1. 夏普市场（低水钱交易所/大庄）的价格共识；
2. 全市场资金流的方向；
3. 自有风控因子（敞口管理、限额模型、已实现盈亏）。

因此你的优势是**相对**的。公开数据建模的现实相对优势量级：

| 证据 | 结论 |
| --- | --- |
| 开源项目 `CODESIGURD/value-bet-model` | 5 轮模型迭代 / 4 种特征增强 / 10 联赛 25 赛季样本外 → **从未达到盈利阈值**（AUC 0.535–0.560），作者公开确认为零结果 |
| 行业共识（OddsShopper 等） | "模型本身不能击败体育投注；优势存在于**价格**而非**选择**" |
| 学术（Whelan, *Estimating Expected Loss Rates in Betting Markets*） | 水钱与实际损失率的关系需按赔率区间分段修正（favorite-longshot bias） |

**关键不对称**：
- 你在**水平**上竞争（预测比赛结果）→ 面对的是已被定价的公开信息，优势 ≈ 0；
- 你在**时间结构**上竞争（微结构信号）→ 这是构想中唯一有价值的方向，但**其收益受 §4.3 的成交裁定封顶**。

## 8. 经济学分析（二）：成本结构与摊销

![图 7 成本结构与摊销平衡](images/fig7_cost_breakeven.png)

### 8.1 月度成本构成

| 项目 | 月成本 (USD) | 说明 |
| --- | --- | --- |
| 行情数据 API（多源冗余） | 250 | 冗余是必需的（§3.2） |
| JEV 调用（约 150k 次/月） | 150 | 高频路径 B |
| **LLM 调用（约 6k 次/月）** | **60** | 低频路径 C |
| 采集基础设施 / 代理 / 算力 | 140 | 浏览器级执行 + 端点池 |
| 存储与监控 | 60 | 时序库 + 告警 |
| **人力摊销（0.2 FTE）** | **400** | 维护端点漂移的持续投入 |
| **合计** | **$1,060** | **$35.3/天** |

**注意两件事**：

1. **模型成本（$210）只占 20%**，基础设施与人力占 80%。**这个系统的成本结构不是"AI 成本"驱动的，而是"维护一个漂移端点集合"驱动的。**
2. 人力摊销是最容易被低估的一项：端点半衰期短、协议会变、反自动化对抗会升级——**这不是一次性开发成本，是持续运营成本**。

### 8.2 摊销：覆盖成本所需的投注量

以固定成本 $35.3/天计，覆盖成本所需日均注数：

| 单注规模 | 优势 +1% | +2% | +3% |
| --- | --- | --- | --- |
| $10 | 353 注 | 176 注 | 118 注 |
| $20 | 176 注 | 88 注 | 59 注 |
| $50 | 71 注 | 35 注 | 24 注 |
| $100 | 35 注 | 18 注 | 12 注 |
| $200 | 18 注 | 9 注 | 6 注 |

**读法**：

- 单注 $10 + 1% 优势 → 需要 **353 注/天**。这个量级在任何平台上都会立即触发风控。
- 单注 $100 + 2% 优势 → 需要 18 注/天。这是**唯一在数量上似乎可行的组合**。
- 但注意：**一旦被降限额（§4.3），单注规模下降会再次推高所需注数**——形成正反馈式的死亡螺旋。

> **成本摊销的结构性矛盾**：可行的投注量需要较大的单注规模，而较大的单注规模会更快触发限额；被限额后又需要更多注数来覆盖固定成本。

## 9. 量化压力测试

### 9.1 参数

| 参数 | 取值 |
| --- | --- |
| 初始银行 | $10,000 |
| 下注频率 | 5 注/天 |
| 单注比例 | 银行 2%（flat，保守） |
| 结算赔率 | 1.95 |
| 模拟时长 | 90 天 |
| 路径数 | 20,000 |
| 日运行成本（情形 D） | $35.3（见 §8.1） |
| 平台跑路/拒付概率（情形 C） | 25%，发生时损失 70% 本金（**保守假设**，见 §9.3） |

胜率由 EV 反推：`q = (1 + EV) / 1.95`

### 9.2 结果

![图 11 蒙特卡洛 2 万次模拟](images/fig11_montecarlo.png)

| 情形 | 90 日余额中位数 | 5 分位 | 95 分位 | **盈利概率** |
| --- | --- | --- | --- | --- |
| A · 无优势（滚球水钱 11.4%） | $3,631 | $1,870 | $7,329 | **0.8%** |
| B · +2% 优势，无平台风险，**不计成本** | $11,259 | $5,577 | $21,858 | 61.4% |
| D · +2% 优势，**扣除 $35/天 成本** | $7,655 | $3,069 | $16,527 | **45.4%** |
| C · +2% 优势，**25% 概率跑路/拒付** | $9,263 | $2,377 | $20,217 | **29.2%** |

**四条关键读法**：

1. **情形 A 是默认结局**：无优势时 99.2% 路径亏损，且亏损是对数坐标下的近似直线——**稳定的指数衰减**。这就是水钱的数学形状。
2. **情形 B 是乐观上界**：即使假设 +2% 优势真实存在且不计任何成本，也只有 61.4% 路径盈利。原因：2% 的优势相对于 2% 的下注比例与赔率波动，信噪比低，**90 天样本量不足以稳定实现期望**。这说明"回测盈利 → 实盘盈利"之间存在巨大方差鸿沟。
3. **情形 D 揭示成本的破坏力**：每日 $35.3 固定成本，把盈利概率从 61.4% 拉到 45.4%——**约 16 个百分点的损失**。而这个成本相对 $10,000 本金（0.35%/天）与 +2% 优势是同一个量级。
4. **情形 C 是叠加后的现实**：平台风险把 61.4% 压到 29.2%。**而 D 和 C 会同时生效**——真实盈利概率应低于任一单项。

### 9.3 敏感性说明

**关于 25% 这个参数**：本报告不给它任何精确性假设，它只用于说明量级。读者可在 `scripts/make_figures.py` 的 `fig11_montecarlo()` 中改为 5%、50% 或与之无关的累积风险模型重跑。**结论方向不变**：只要该风险不是零，它就会显著压低盈利概率。

更贴近现实的建模方式是把"账户风险"视为与**盈利水平正相关**的累积过程——因为触发限额与拒付的因素是**注单质量（CLV）**，而非账户余额。也就是说：**你的成功本身就是风险的触发条件**。本报告的固定概率模型实际上是**乐观简化**。

### 9.4 微结构信号能改变结论吗？

这是本方案唯一可能改变结论的方向，值得单独量化。假设微结构信号能提供额外的相对优势 ε：

| 总相对优势 m_needed=11.4% 下 | 需要的 ε | 现实评估 |
| --- | --- | --- |
| 打平 | 11.4% | 极不可能（公开数据 0–2%） |
| 净收益 +2%（扣成本后） | ~13% | 更不可能 |
| 净收益 +2%（假设交易所 3% 水钱场景） | ~5% | 仍远超公开数据可得水平 |

> **结论**：微结构信号在**理论上**是正确的竞争维度，但要把打平所需的 11.4% 相对优势大部分由它提供，**没有公开证据支持**。工程上应该把它当作**边际改善**（提高 `q_fill`、降低无效调用、改善 S6 执行过滤），而不是当作优势来源。

## 10. 可行性评分与结论

![图 12 架构层 × 技术/经济学维度评分](images/fig12_feasibility_heatmap.png)

| 架构层 | 技术可实现性 | 经济学有效性 | 工程稳定性 | 长期可维护性 |
| --- | :---: | :---: | :---: | :---: |
| L1 数据采集（实时倍率） | **4** | 3 | 2 | 2 |
| L2 特征/微结构（去水·漂移） | **5** | 2 | 4 | 3 |
| L3 决策（LLM+JEV） | **4** | **1** | 4 | 3 |
| L4 经济学算法栈 | **5** | 2 | 4 | **4** |
| L5 下单执行（自动投注） | 2 | **1** | 1 | 1 |

**评分口径**：0 = 不可行 / 5 = 完全可行。作者基于本报告证据的主观评分，可通过 `data/feasibility_scores.csv` 复核调整。

**读图要点**：

1. **「可实现」与「有效」是两条完全不同的曲线。** L2、L4 技术上都是 5 分（确定性计算、有严格最优解），但经济学有效性只有 2 分——因为它们处理的是**给定 `p_model` 之后**的问题。
2. **L3 的分裂最明显**：技术 4 分 / 经济学 1 分。混合决策架构的**工程答案是对的**（三路分流、LLM 不进关键路径），但它**不改变期望值的符号**。
3. **L5 全面低分**：技术 2 分（无 API、状态机脆弱）、稳定性 1 分、可维护性 1 分。**这是整个系统的单点否决项**——不是因为它难写，而是因为它由对手方裁定。

### 10.1 结论

| 问题 | 回答 |
| --- | --- |
| **Q1 能不能实现？** | **技术上可以，但分层差异巨大。** L1–L4 可实现、可维护；L5 存在结构性的不可控（接受延迟、改价、拒单、限额）。 |
| **Q2 经济学上是否正期望？** | **否。** 在盘水钱均值 11.4% → EV = −10.23%；打平需相对优于庄家定价模型 11.4%，公开数据可得优势 0–2%。 |
| **架构设计正确吗？** | **分层设计正确，且能得到严格最优解。** LLM + JEV + 经济学算法的三路分流是本类问题的最优工程答案（§5.2）。但它优化的是一个**负期望系统**。 |
| **最有价值的部分是什么？** | **L4 经济学算法栈**（可维护性 4 分）与 **L2 特征/微结构**（可实现性 5 分）。这两层的方法论可以完整迁移到其它正期望场景。 |

### 10.2 直接回答原构想

> **不可行——但原因与多数直觉相反。**
>
> 它不是"技术做不到"，也不是"模型不够强"。
> - **架构是对的**：LLM 承担非结构化低频推理、JEV 承担高频结构化判断、经济学算法承担确定性最优计算——这个分流是正确的，而且是可推导的（§5.2）。
> - **瓶颈不在模型侧**：你的决策链只占总延迟的 **6%**（1.8s/29.0s），模型优化的天花板是 12%。
> - **失败点在两处结构性约束**：
>   1. **定价**：打平需 11.4% 相对优势，而可得优势 0–2%（差一个数量级）；
>   2. **成交**：5–20s 的接受延迟 + 改价 + 拒单 + 基于 CLV 的降限额，使"捕捉调价瞬间"的收益在成交前不可实现。
>
> 叠加固定成本（$35.3/天）后，**即使假设优势真实存在**，90 天盈利概率也从 61.4% 降至 45.4%，再叠加平台风险降至 29.2%；而假设优势不存在（更接近现实），盈利概率是 **0.8%**。

### 附录 B：公式汇总

**水钱与期望值**

$$S=\sum_{i=1}^{n}\frac{1}{o_i}=1+m,\qquad \mathrm{EV}=p\cdot o-1=-\frac{m}{1+m}\quad(\text{当 }p=p^{\text{fair}})$$

**打平条件**

$$\mathrm{EV}>0\iff p>\frac{1}{o}=p^{\text{implied}}=\frac{p^{\text{fair}}}{1+m}$$

需要的相对优势恰为 `m`。

**分数 Kelly**

$$f^{*}=\lambda\cdot\frac{b\,p-q}{b},\qquad b=o-1,\ q=1-p,\ \lambda\in[0.2,0.5]$$

**有效期望（含执行过滤）**

$$\mathrm{EV}_{\text{eff}}=q_{\text{fill}}(s)\cdot\mathrm{EV}-\text{cost}_{\text{exec}},\qquad \frac{\partial q_{\text{fill}}}{\partial \mathrm{EV}}<0$$

其中 `s` 为单注规模；`q_fill` 随 `EV` 递减（§4.3 的机制），且随 `s` 递减（限额）。

**成本摊销所需注数**

$$N_{\text{required}}=\frac{\text{cost}_{\text{day}}}{\mathrm{EV}\cdot s}$$
