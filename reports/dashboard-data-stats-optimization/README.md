# 决策链路与看板数据统计优化

`ai_football` 决策链路（**盘口变动触发 → 入场门控 → LLM 裁定 → 台账结算 → 前端看板**）的
缺陷定位、根因分析与修复报告。

针对用户报告的四个现象：

1. 算法应在**盘口变化时自动触发**；
2. 几十场比赛却**没有一条买入建议**；
3. 怀疑 **LLM 判定不准**，要求记录决策与实际结果做本地统计；
4. 页面**看不到每场比赛每个盘口的实时信息**。

## 一句话结论（非技术版）

这套系统像个「看盘分析师」：先用**公式**筛出值得看的盘口，再交给 **AI 顾问**判断。

用户报的四个问题，背后是 **8 处「漏水」**。其中最关键的一点：

> **问题 ② 和 ③ 是同一个根因** —— 系统把**比分**告诉了 AI，等于**把答案写在题目旁边**。
> AI 因此给出大量「说 100% 会赢、市场只给 35%」的**假建议**。
> 这既解释了「几十场都没建议」，也解释了「建议看起来不准」。
>
> 结论：**在修好这个泄露之前，任何命中率统计都没有意义**（相当于把答案泄给考生再统计分数）。

修好之后的实测变化：

| 事情 | 之前 | 现在 |
| --- | --- | --- |
| 能收到行情的比赛 | 2 场 | **82 场** |
| 服务器负担 | 打满、健康检查**超时** | 空闲（7.6%），检查 **3 毫秒** |
| 正常盘口被挡在门外 | 约 35% | 约 **5%** |
| 账本记录 | **0 条** | **526 条** |
| AI「100% 把握」的假建议 | 43 条里 **26 条** | **0 条** |
| AI 理由里直接写比分 | 有 | **0 条** |

## 结论速览（技术版）

四个现象背后是 **8 个真实缺陷**，其中 2 个是灾难级：

| 缺陷 | 性质 | 关键证据 |
| --- | --- | --- |
| D1 大响应 `IncompleteRead` 未被捕获 | 链路断链 | 实时订阅只有 **2** 场（应 40+） |
| **D2 比分区泄漏进 LLM 提示词** | **灾难级** | 理由原文「终场0:0，小球」，`p_llm=1.0` vs 市场 `0.35` |
| D3 去水分歧用**绝对** 3pp 阈值 | 逻辑错误 | 69/71 场被 `devig_unreliable` 误杀 |
| D4 已结束赛事仍被当进行中分析 | 数据污染 | 快照来自两天前、`state` 仍 `active` |
| D5 收盘赔率从未留痕 | 功能缺失 | CLV 永远为 `None` |
| D6 台账在配置注入前创建 | 初始化时序 | 启动日志「赛后结算未启用」 |
| D7 启用变动触发后 CPU 打满 | 性能退化 | CPU **165%**、`/health` 超时 40s |
| D8 `/board` 存在但前端未接线 | 交付缺口 | 导航仅 3 个视图，0 处 `/board` 调用 |

修复前后实测：

| 指标 | 修复前 | 修复后 |
| --- | --- | --- |
| 实时订阅场次 | 2 | **82** |
| 容器 CPU | 165% | **7.6%** |
| `/health` 延迟 | >40s（超时） | **~3ms** |
| 门控误杀率 | 35% | **5%** |
| 台账条目 | 0 | **526**（524 条含收盘赔率） |
| 决策触发来源 | `cycle`（600s 轮询） | **`price_change`** |
| `p_llm≥0.9` 假建议 | 43 条中 26 条 | **0** |
| 含赛果的 LLM 理由 | 3 条 | **0** |

## 一键复算

无需联网、无需第三方库（仅标准库）：

```bash
python3 reports/dashboard-data-stats-optimization/scripts/analyze_fixes.py
```

输出门控阈值影响、`p_llm` 分布、被拒原因分布三项量化结论。

> 数据源为 `output/decisions.json`（生产决策落盘，已被 `.gitignore` 忽略），
> 文件缺失时脚本会明确报错，不会输出空的假结论。

重新生成 HTML：

```bash
python3 reports/dashboard-data-stats-optimization/scripts/md_to_html.py \
        reports/dashboard-data-stats-optimization/REPORT.md \
        reports/dashboard-data-stats-optimization/REPORT.html
```
