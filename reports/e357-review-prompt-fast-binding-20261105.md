# E357 审核提示与完整检索绑定契约一致性

更新时间：2026-11-05 20:27 UTC。状态：研究中。

目标：消除高优先级系统提示与既有 expert-review 技能之间的冲突，完整搜索已由服务端唯一绑定后不再强制重复 resolve_match。责任目录：services/api、tests；依赖现有完整分页、双方队名唯一核验、绑定证据、盘口读取及终审校验。

当前证据：系统提示仍写“完整分页后必须调用 resolve_match”；技能第3项和 MCP search_matches 契约已允许 search_complete=true 且 resolution.resolved=true 时复用服务端绑定。现有 test_search_resolution 覆盖不调用独立 resolve 即可读盘录入与通过 completion_issues，也覆盖未完整分页、错误双方、歧义、权限丢失、完场不读盘。真实图片审核中仍发生搜索后重复独立解析；不能把这一观察推断为全部模型延迟的原因。

缺口：实际审核上游模型耗时曾达34.820秒，完整链路51.130秒；此修复只能消除不必要步骤，不能据此声称三秒达标。提示摘要属于配置来源，发布前必须核验真实活动配置的来源及消费者一致性，不能绕过摘要校验或伪造比较报告。

设计决策与实现：系统提示明确首次搜索可传原文可读双方；只有完整分页且结构化服务端唯一解析成功才能复用绑定；同场复用，不根据模型自行判断跳过解析。没有双方、未解析成功或歧义仍执行 resolve_match。完场、取消、报价过期、无唯一绑定继续保持不可投注。

验收：请求实际发出的系统提示遵守上述契约；既有完整搜索直连读盘及所有拒绝场景保持；配置来源与版本测试通过；代码冻结后完整隔离回归；同源候选的实际配置摘要和生效路径核验后才发布；自然真实消息另记完整观察窗，不以合成测试代替命中验收。

失败处理：保留失败输出和原检查，修复后重跑；冻结/配置来源验证失败不发布。任何外部模型或样本不足单列，不降低服务端分页、绑定或新鲜度校验。
